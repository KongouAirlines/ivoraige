# ADR-0003：0.1.x 运行时迁移门禁

日期：2026-11-06｜状态：采纳，记录 2026-11-05 确定的实施顺序；不批准具体运行时升级。

## 背景

[ADR-0001](0001-runtime-selection.md)确定 Cordis 与 DSH 复用路线，[ADR-0002](0002-plugin-composition-0.1.0.md)确定能力组合边界。本决策只调整升级时机，不替换两项架构选择。[运行时评估](../plan/0.1.x/runtime-sequence.md)曾建议在基础改造前段尽早验证并采用配套候选；候选仍需 Core/Loader/vendor/DSH 成套验证，不能从 RC 编号推断已兼容。本项目保留固定 DSH pin `639ed015397290b3745d163aafe02ffee4aa3f84` 下的已知基线。

## 决策

只有 **Cordis 上游正式稳定且 DSH 已完成对应迁移** 两个条件同时满足，才评估 ivoraige 的依赖迁移。两条件只触发评估，不自动升级：采用前仍须固定精确版本/补丁元组，通过单一运行时、生命周期/配置、Records/快照、三入口、包闭包与兼容回退门禁，并以独立变更交付。

固定 pin 的契约澄清、基础回归及获准功能切片不因等待迁移而全部停下；需要上游缺失能力的功能应明确限制、阻塞或另行评估最小修复，不能写成已有能力。四接口目前仍是未实现、未冻结的 RFC，本决策本身不启动接口实现。冻结配置首版按 [RFC 的一致性/阻塞门禁](../requirements/0.1.x/control-admission-rfc.md#固定-dsh-下的冻结执行门禁)验证，不把升级 DSH 作为默认解法。

## 权衡与重评

- 保留当前可复现基线，让功能与运行时问题分别归因，避免跟随未定候选或形成无明确收益的长期分叉。
- 接受未来可能发生的适配与兼容范围调整；旧/新组合、公共组件包替换及数据迁移各自保留证据，不混成一次无法归因的升级。
- 双条件满足后重新核验上游实际提交、迁移范围和维护成本；基线出现实质安全/正确性阻塞时单独评估补丁或调整此决策，不能据此默许提前升级。

本 ADR 取代 runtime-sequence 中早迁的优先顺序，保留其历史源码证据与验证矩阵；它不表示候选、协议扩展或四接口已通过本项目运行验收。
