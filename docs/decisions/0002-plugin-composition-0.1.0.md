# ADR-0002：0.1.0 能力组合与插件边界

日期：2026-10-13｜状态：采纳，指导 0.1.0 后续实施。

## 背景

ivoraige 是供人和 AI 共用的翻译与文件处理基础设施。学习者、学生、科研用户、兴趣翻译者会按任务组合文本、PDF、术语、工作台和自动化能力；小说与科研文献都可能经过同一翻译内核。产品价值来自复用成熟工具、按需安装和选用，以及一次接受译文后由不同输出共享，而不是预装所有格式或为每种入口建一套流程。

[v2.0 设计](../requirements/v2.0/01_design_v2.0.md)确定一个内核和 CLI、MCP、WebUI 入口，[ADR-0001](0001-runtime-selection.md)确定 Cordis 与 DSH 复用路线。当前 `src/app.mjs` 是组合根，`parse` / `outputs` 是适配器注册表，`operations` 为入口提供内核操作，PDF 通过可选配置、sidecar 和安装组件接入。现有边界还需明确能力归属、缺件隔离和生命周期，否则新入口或格式容易把具体实现写入通用流程。制定本决策时 PR #18 的 MCP 实现尚未合流；2026-10-17 合流复核后，源码按下述边界提供 MCP，实际验证与发行附件范围仍由阶段记录和能力表说明。

## 决策

1. **按可选能力组合，而非按函数拆插件。** 独立安装、选择、依赖或生命周期有意义时才划出插件边界。一个格式适配器可内部保留普通函数和类；不为假设中的第三方市场、任意热卸载或未来宿主预建通用框架。优先使用已成熟且经过实际契约核验的 DSH/Cordis 插件或其他工具，项目实现跨工具的装配与领域逻辑，例如译文复用、来源绑定和同源输出；后续基础文件处理按独立能力选择，不强迫它经过翻译任务。
2. **组合根负责选择具体实现。** 启动/安装层可以导入和配置 `Pdf`、DSH provider、sidecar 等具体模块，并决定哪些能力可用。通用服务只依赖所需的服务或注册契约，不根据 `pdf`、特定模型商或某个入口分支。能力可由 provider、格式适配器或外部桥接模块贡献到既有契约；入口枚举安装后的操作并做协议映射，不复制业务规则。格式专属的匹配、解析、来源定位、译文校验、回放及其文件/子进程资源由适配器承担；记录、复用判定、快照和任务编排仍由共享内核负责。
3. **依赖和不可用状态是契约的一部分。** 贡献者声明必需与可选依赖、服务名/注册接口、激活条件和失败语义。缺少可选组件时基础程序与无关能力继续运行；能力列表或状态可以说明原因，在实际选用时返回明确错误。不能把未安装、配置失败或未验证的能力默认为可用，也不能让格式插件通过隐式全局引用取得模型或凭据。导出适配器只接收已冻结数据，不取得翻译模型服务。
4. **声明并完成生命周期。** 注册、路由、监听、任务控制器、设置/UI 贡献、文件与子进程都要有明确的所有者和清理动作；失败启动和正常退出均释放已取得的资源。拥有运行任务的服务先停止/等待任务，再释放其依赖、上下文及存储锁。按需安装允许“安装后重启启用”；只有产品实际支持运行时移除时才验收热卸载。验证选中、缺失、失败以及重新启动后的行为，以受影响边界为限。
5. **宿主边界保留选择权。** 未来可把 ivoraige 作为 DSH 插件安装，但这是低优先级集成选项。保持内核服务与宿主无关的业务契约，复用 DSH 上游提供的权限、凭据、设置和任务边界；对外入口依宿主授权暴露操作，不另写平行权限体系。是否沿用、嵌入或调整现有前端由届时的宿主接口与体验验证决定，本决策不预设重写 WebUI。

## 具体应用

- **PDF：** 组合根按安装状态挂载 PDF 能力；PDF 适配器负责 BabelDOC 来源绑定、校验和冻结回放，sidecar 仅通过协议调用。未装 PDF 组件时文本导入、翻译和 MD/JSON 输出仍可用，选用 PDF 时给出明确状态/错误。PDF 导出无法访问 LLM，重放同一快照不追加模型请求。组件更新若需重启，状态应明确提示。遇到公式或布局问题，先区分调用时机／适配兼容和上游解析限制：修复我们拥有的边界，后者通过可恢复警告与实际效果说明，不另造 BabelDOC 解析器，也不无依据地阻止可继续的导入或翻译。来源归属、协议结构和冻结输出正确性仍由对应模块验证。
- **MCP：** 作为入口插件把已安装内核操作映射成规范工具/资源，沿用协议错误、授权和取消语义；不内嵌 PDF 或模型业务分支。MCP 缺席不影响 CLI/HTTP；某一格式缺席时不将其虚报为可调用能力。当前 stdio／Streamable HTTP 实现通过独立能力注册映射现有内核；新增工具仍按此边界核查实际行为。
- **外部桥接：** Zotero 等桥接只负责来源事件、参数及授权边界到内核契约的映射；它不拥有第二份修订、翻译或导出流程。具体桥接在需求与宿主 API 验证后选择实现。

## 验收与取舍

新增能力至少核对：组合根的选择条件；依赖声明与缺失状态；贡献注册及释放；现有基础组合不回归；选中路径和失败/重启路径；入口调用同一内核结果；用户文档中的安装与限制。按能力风险选择定向测试、冒烟或实际端到端验证，不要求每次重跑不相关的发行验收。同步更新英文和中文 README 以及受影响用户指南；版本阶段记录保存实测证据，能力地图保存当前能力边界。

这种分层让组合根可以认识具体插件，通用层保持稳定，但仍允许少量务实的内核服务。我们不承诺任意动态装卸、所有格式互通或所有入口同时实现；新增跨引擎来源映射、权限范围或宿主插件形式时，应以实际契约和验收结果修订相关设计。
