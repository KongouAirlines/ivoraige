# 0.1.0 安装与首次启动体验规划

日期：2026-10-12。状态：实现、本机验收与 Windows Sandbox 离线闭环通过，PR #17 待 review。实施分支：`codex/0.1.0-installation`；基线：PR #10／#12 已合入的 `main/4df1d72`。软件版本仍为 `0.1.0-dev.0`。本阶段先验收 Windows，保留三平台目标；不把 Node 三平台 CI 等同于原生 PDF 发行验证。

## 目标与边界

用户无需克隆仓库、构建源码或自行安装 Node／Python，即可启动工作台。首次不下载全部插件：默认具备文本导入、翻译审校、持久化和 MD／JSON 冻结导出；用户选择 PDF 后才取得其运行时和资源。首次启动可跳过模型配置，稍后配置后再翻译。

本阶段完成官方 PDF 组件的按需安装闭环，复用 Cordis 可选服务及 DSH 配置、凭据、任务基础设施。不建设第三方插件市场或通用包管理器，不拆分每一个小型内核依赖。MCP、双语 PDF、OCR、MinerU、自动后台更新、安装器外壳和三系统同时发布不作为本轮完成条件。

## 分发与仓库可见性

不要求公开源码。按需下载的是按版本发布的构建产物及资源，而非 Git 分支或源码目录。源码与发行仓库可以相同，也可以分离；配置保存发行源，不硬编码当前私有仓库为唯一入口。

本阶段只按当前私有仓库 GitHub Releases 设计和验收，暂不考虑独立公开发行仓库，也不改变源码可见性。基础程序由获授权用户从 Release 下载；PDF 组件在程序中按需下载。用户提供有该仓库 Contents read 权限的个人凭据，复用 DSH credentials 保存。默认固定 Release tag，不自动追踪 latest；本地组件包导入作为离线补充。

GitHub Release asset API 的私有资源要求授权，细粒度凭据需要 Contents read。见 [GitHub 官方文档](https://docs.github.com/en/rest/releases/assets#get-a-release-asset)（2026-10-11 核对）。不能把维护者令牌内置在客户端；凭据不写日志或随跨主机重定向传递。授权失败提供重新配置入口，不把 PDF 下载失败升级为基础工作台启动失败。

发布包与权重保留各自许可要求。私有在线下载属于本阶段验收范围，不再以未来公开发行位置作为前置条件。
## 安装内容与首次流程

1. 基础发行包包含内核、运行时、WebUI 和默认文本能力。轻量 PDF 接入描述可随内核提供，未装组件时不启动 Python、不下载权重。
2. 双击默认启动本地服务并打开浏览器；已有实例尽量打开现有工作台，不启动第二个数据库所有者。无头启动保留 CLI 入口。
3. 首次显示简短引导：数据位置、可跳过的模型配置、可选 PDF。基础工作台不因 PDF 下载失败而不可用。
4. PDF 卡片显示状态、版本、适用平台、预计下载量以及安装／选择已有组件入口。下载量来自发行清单，不编造体积。
5. 用户选择安装后，显示下载、校验、安装和验证进度；支持取消、失败后重试，完成后保存配置。无需手写 JSON 或复制启动命令。
6. 首期允许提示一次应用重启使组件生效，重启必须先处理活跃任务和未保存编辑；不承诺热替换运行中的 sidecar。再次启动无需重复选择路径或下载。
7. 安装程序、用户数据、组件版本和下载缓存分目录保存。升级／替换程序不覆盖数据库、修订、快照或凭据；卸载组件不删除用户文档和 PDF 原件。

## 构建与安装机制

- 按 v2.0 设计先验证 Node SEA 与现有 DSH vendor、SQLite、静态资源及路径发现的依赖闭包。选定构建工具链后固定版本，不能把开发机 PATH 当作发行依赖。
- PDF 运行时按平台构建独立组件，优先验证既定 PyInstaller 路线；onefile 与目录包的启动耗时、体积和依赖完整性需实测。若需调整设计中的包装形式，在同一实现提交更新设计依据，不为了单文件形式牺牲可运行性。
- 组件包与字体／模型资产分别版本化，明确所需资源集合和许可。用户选择 PDF 才下载其依赖；不沿用“一次预热所有未来引擎”的默认行为。具体字体和模型拆分以 BabelDOC 实测依赖为准，不承诺未验证的按页下载。
- 首期清单仅服务官方组件，包含组件 ID／版本、平台架构、内核／sidecar 协议兼容范围、资产地址、字节数、SHA-256 及许可说明。固定版本解析，不对每次导入调用 latest。
- 安装先下载到应用管理的暂存目录，完成一次完整性与路径检查后发布为版本目录，最后更新激活配置；失败或取消不覆盖已有可用版本。解压拒绝目录穿越。下载校验不扩展成每次翻译都扫描所有组件。
- 只检查启用组件的必要可用性。启动时轻量读取安装记录，真正加载时验证握手；不重复下载已有可用资源。离线时已安装组件可用，缺失组件保持可识别的未安装状态。
- 组件管理通过内核服务提供给 CLI 和 WebUI；页面只转发操作。安装任务尽量复用 DSH jobs；不另建凭据库、任务队列或模型访问层。安装的活动状态不能伪装成文档翻译任务。
- 普通组件包导入与下载走同一校验／激活路径。首期不做差分更新、任意第三方脚本安装、依赖求解或隐式执行远端脚本。

## 分阶段退出条件

| 阶段 | 工作 | 必须看到的证据 |
|---|---|---|
| I0 发行可行性 | 固定目标 Windows 架构，试构建内核和 PDF 组件，核对依赖／许可／资产大小 | 不依赖开发 PATH 的可启动产物；记录打包方式、大小、冷启动和实际限制 |
| I1 基础安装与启动 | 程序与数据分离，默认启动浏览器，初次配置与实例复用 | 无 Node/Python/仓库的环境完成 TXT/MD 闭环；重启读回配置和接受修订 |
| I2 PDF 按需安装 | 官方清单、下载及本地包安装、任务进度、取消／重试、版本激活 | 初次无 PDF 下载；选择后安装对应组件；断网或失败不损坏旧版本和文本功能 |
| I3 设置与首次体验 | PDF 设置卡片提供操作，保存路径及状态，简化引导 | 普通用户不使用准备脚本、不编辑组件 JSON；进度与错误可理解，提示重启时不丢编辑 |
| I4 交付验收 | 干净环境安装、更新、重启与完整 PDF 流程 | 同快照三格式导出、重导出零模型调用；更新程序保留数据；文档和许可随包；PR 等待 review |

## 验证与停止节点

- 自动回归覆盖组件缺失、版本不兼容、下载失败／取消／重试、坏包及解压越界、已有版本保护、离线已安装、重启读回、无 PDF 时的文本功能；不以拒绝 BabelDOC 解析不完美作为验收手段。
- Windows Sandbox／VM 或等价干净用户环境记录具体系统和架构；移除 Node、Python、uv、源码及开发缓存依赖。仅修改 PATH 的探针不足以宣称干净环境通过。
- 在干净环境使用原创少页 PDF 完成导入、少量翻译、人工编辑／接受、导出下载、重启及冻结重放。优先沿用已有样本；真实模型预算在执行目标中明确，不因安装测试默认追加大量请求。
- 确认首次基础启动未拉取 PDF／MinerU／全部字体权重；记录首次下载与再次启动的网络行为。以实际组件依赖定义“必要资源”。
- 确认升级前后文档、配置、凭据引用及旧快照可使用。手动安装新版先行，不把自动更新系统绑定为退出条件。
- 完成 I0～I4 后提交面向 main 的 PR，提供安装产物位置、实测平台、体验步骤、下载体积、验证证据与限制；等待 review，不自行合并或继续 MCP。实际发布公共附件或改变仓库可见性不包含在本规划提交中。

## 既有事项关系

PDF P5 原先把双语和分发并列；本计划承接其分发部分，双语仍独立待验收。不重新修复 BabelDOC 上游解析。`pdf-partial-line-coverage`、`pdf-source-open-race` 仍保留原状态；安装数据路径验收引用 `pdf-store-relocation`，不能用本次规划提前关闭跨平台发行条件。MCP 在本阶段之后接入同一已部署内核。

## 实施证据（2026-10-11）

- Windows 11 Pro 10.0.26300 x64：基础包自带 Node 26.7.0，PDF 使用 Python 3.13.12／BabelDOC 0.6.4／PyMuPDF 1.26.7／PyInstaller 6.22.3。Node SEA 实测遇到 ESM bundle 的动态 `require("process")`，CJS 又不支持现有顶层 await；本阶段采用可运行的目录 ZIP，不宣称单文件完成。
- 自动回归 212/212 通过；下载进度文案调整后相关组件测试 14/14 通过。浏览器验证初次引导、数据路径、未安装状态、未保存内容保护，以及安装失败后保留路径重试。
- 发行包使用隔离用户目录、仅 System32 的 PATH，通过真实 HTTP 完成文本导入、人工接受、MD／JSON 冻结输出及重启；复制程序目录后沿用原数据目录仍可读回。此为同版本程序替换，不是跨版本数据迁移。
- 完整发行包探针 `http-pdf-smoke-5` 通过：原创两页重复文本／公式／双栏样本捕获并接受 12 个单元，PDF／MD／JSON 共用冻结快照；重启后修改修订再重导出，MD／JSON 字节相同，两页 PDF 渲染 PNG 的 SHA-256 逐页相同（PDF 元数据导致文件摘要不同）。两页目检保留页面与双栏；人工前缀会使独立公式文本换行，这不是科学排版质量验收。导入约 24.7 秒，导出约 23～26.1 秒；四次基础启动 590～834 毫秒。所有探针模型调用为零。
- 独立发行运行时追加一次 DeepSeek Flash 翻译：112 输入／6 输出 token，累计共享预算 13/30 次；人工编辑接受后两次三格式冻结导出均零调用，快照一致。记录在 `live-report.json`。修复冻结 Python 缺少 `multiprocessing.freeze_support()`、bitstring 动态模块和 tiktoken 插件遗漏；未改 BabelDOC 解析策略。
- 基础 ZIP 约 62.6 MiB；可选 PDF 运行时 201,096,363 字节、资源 235,512,400 字节，合计约 416.4 MiB。完整上游 Node／Python／Python 依赖／字体／模型／CMap／分词器许可与来源随对应包保存。末次归档更新仅补 Python 许可，运行代码和样本使用的资产不变。
- 最终 npm 包隔离安装验证 51 文件通过；自定义 `IVORAIGE_DATA_DIR` 下 CLI 与默认启动使用同一数据库的回归 2/2 通过。私有 Release 在线下载安装在上传产物后单独记录。
- 私有大附件直连探针失败后，补充下载中断的可操作提示及回归，相关测试 15/15 通过。发行启动器默认使用已有 HTTP(S) 代理环境配置并绕过本地工作台，保留显式禁用选项；实际 CMD 启动、文本能力及已有实例复用通过。代理下载中的取消也实际通过；详细网络诊断不暴露凭据或附件签名链接。

## Windows Sandbox 补充验收（2026-10-12，PR #17）

- 真实 Windows 11 Enterprise x64 Sandbox，build 26100，PowerShell 5.1.26100.9549；未发现预装 Node／Python／Git，网络禁用，只读映射发行包和组件。首次失败不是驱动缺失：受管理来源的双哈希长文件名被 BabelDOC 重复用于工作目录及输出名，PyMuPDF 保存路径过长；异常栈持有输出句柄，后续 `rmtree` 的 WinError 32 又覆盖了原异常。另确认冻结子进程缺少 Hyperscan wheel 的 `hyperscan.libs` DLL。
- 每次调用把来源复制到私有运行目录的 `input.pdf`，保持受管理原件、来源绑定与冻结快照不变；不修改上游解析／翻译算法，不要求用户修改系统长路径策略。清理失败不覆盖已有引擎异常，成功路径的清理错误仍报告。构建使用 PyInstaller 的 delvewheel 收集方法带入 Hyperscan DLL；冻结 EXE 已检查包含短路径代码。
