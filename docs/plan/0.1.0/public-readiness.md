## 2. 公开暴露面和优先级发现

### 2.1 公开范围

公开会暴露现存开发分支、tag、归档 MVP 和可达历史，不限于默认分支。Issue／PR 正文、评论和保留引用、非 draft Release 及附件、Actions 历史与日志同样属于检查面。删除分支、关闭讨论或删除 HEAD 文件都不等于移除历史。

API 快照显示 Wiki、Discussions、Pages 关闭；Wiki Git 入口返回不存在；当前 forks、Actions artifacts 和 caches 均为 0。没有发现讨论上传的 GitHub 附件或云盘分享链接。不能由此推断从未有过后来被删除的内容。

GitHub 官方说明公开后任何人可 fork，Actions 历史／日志对所有人可见；私有仓库的 `allow_forking:false` 不能维持公开后的保密性。Actions artifacts 的下载者仍需登录并拥有读取权限。见[可见性规则][visibility]与[产物下载规则][artifacts]。GitHub 设置中的秘密值不会因为可见性切换自动变成公开文件，但工作流输出或提交中的值属于另一条暴露路径。

### 2.2 优先级口径

- **必须处理／决定：** 对计划保留的公开范围存在未关闭的权利、隐私或分发前置条件；可以通过缩小首轮范围关闭条件，不预设大规模改造。
- **建议同步处理：** 不阻止 GitHub 技术上切换，但影响公众安装、说明可靠性或日常维护，应在对外推荐使用前完成。
- **后续完善：** 可以随预览持续改进，不纳入本轮公开最低门槛。
- **已有措施足够：** 保持现状；仅当证据或风险变化才重新评估。

下列 F 编号仅用于本文定位，不是需求 v1.0 的 F-01～F-44，也不是新增 follow-up ID。

### F-A 项目自身授权尚未明确

- **事实与证据：** 检查到的根目录／历史没有项目自身 LICENSE，仓库 API 返回 `license:null`；[package.json](../../../package.json) 为 `private:true`，这是 npm 发布保护，不是项目许可或 GitHub 可见性设置。[THIRD_PARTY.md](../../../THIRD_PARTY.md)不能代替项目自身授权。历史有多位作者，未找到统一贡献授权流程。
- **根因与责任边界：** 所有者尚需明确对外授予的权利，以及已有代码和设计文档的权属。没有 CLA／DCO 不证明贡献无效，作者元数据也不证明可以任意统一改授许可。
- **影响范围：** 第三方修改、再分发和贡献；不属于 GitHub 切换按钮的技术故障。
- **优先级／是否阻碍公开：** 正式开源前必须决定；仅公开供查看可以保留权利，但不能宣称自由复用，且不能免除第三方组件义务。
- **处理方案：** 所有者选择项目许可并确认贡献授权；根许可、包说明及发行声明保持一致。无需默认引入复杂 CLA 平台，也不因公开仓库而自动移除 npm 的 private 标志。
- **验收方式：** 从根目录和发行说明可以直接找到明确授权；已有贡献的适用授权得到确认。依据[GitHub 许可说明][licensing]。
- **未知与决策：** 尚未核验贡献者合同、单位权利或商业许可；不得代所有者选择 MIT、AGPL 或其他许可。

- **根因与责任边界：** 上游定义许可证；本项目负责自己实际分发的组合、许可通知及对应源码可取得性。资源表不是对实际归档完整性的自动证明。

- **优先级／是否阻碍公开：** 若首轮保留 PDF 二进制附件，应在切换前关闭该核验缺口；否则先暂停其公众分发。过去私有分发给接收者的义务不会因此消失。

### F-D 安装器仍主动要求 GitHub token

- **事实与证据：** 调查时匿名 Release API 返回 404，符合私有仓库预期。[fetchRelease](../../../src/component-package.mjs)在网络请求前拒绝无 token 调用，requestHeaders 始终生成 Authorization；UI 和安装指南按私有 Release 授权设计。
- **根因与责任边界：** 属于本项目组件下载和交互策略，不是 DSH 缺少另一个凭据后端。仓库公开只改变 GitHub 访问条件，不会删除代码里的前置检查。
- **影响范围：** 无 token 公众在线安装 PDF；不影响已有离线安装路径，也不表示公开后用户仍必须成为协作者。
- **优先级／是否阻碍公开：** 不阻止源码公开；阻碍承诺无令牌在线安装，建议公众试用前处理。
- **处理方案：** 使用现有服务支持匿名请求，显式配置的 token 为可选；继续由 DSH 保存凭据，保留跨域重定向不转发凭据、清单／摘要校验、取消、重试和离线安装。
- **验收方式：** 无 token 公开源安装通过；私有源、有 token、限流、失败及本地安装仍可理解且可恢复。
- **未知与决策：** 切换前无法针对本仓库完成真实匿名成功路径；先用受控响应测试，公开后进行真实验收。不新增静默调用本机 gh 凭据的行为。
