# 0.1.0 基础候选规划

本页新增于 2026-10-20，记录待实施的基础体系范围；与同目录已完成阶段的历史记录分开。package.json 已为 0.1.0 不代表本页目标已经实现，也不证明同名版本可在 npm 发布。候选版本与后续范围见 [0.1.x 分期](../0.1.x/releases.md)，执行状态仅见[工作包表](../0.1.x/work-packages.md)。

## 交付目标

将已有工作内核整理为 Cordis 管理生命周期的可组合宿主：选装业务能力和 CLI/HTTP/MCP 入口，复用 DSH 服务及 AppBoot/Loader，不造第二套 DI、加载器或任务内核。保留 Records、修订/接受、适用性复用与冻结导出，以独立小 PR 完成最小闭环，不以全面重写达成。

| 切分 | 范围与验收 | 不做项 / 回退 |
| --- | --- | --- |
| P01 基线与运行时选择 | 先在旧 pin 固定回归；前段单独评估并优先完成有收益、门禁通过的配套 Cordis 迁移；服务/插件/inject/disposer 对照、单一运行时成立 | 不把升级和业务改造合成一个 PR；若要长期维护明显分叉又无明确收益，保留旧 pin，记录证据与重评触发，详见[早迁/晚迁取舍](../0.1.x/runtime-sequence.md) |
| P02/P03 领域兼容与适配器 | 旧库、来源绑定、冻结快照和旧 TXT/MD/PDF 路径回归；导入从 Records 分离，format 与 adapterId 分离；原文结构化模式不要求 targetLang/翻译插件 | 不实现完整项目/术语管理或提前迁移旧用户库；保持旧读路径及备份恢复，不以代码降版代替数据回退 |
| P04 入口与事件 | 可选 CLI/HTTP/MCP 入口受 Cordis 管理；bootstrap/help/修复通道独立；operation/capability 是领域描述，业务 envelope 与进程内通知边界明确；V03 同步竞态覆盖 | 不新增私有插件框架或持久事件平台；保持旧协议映射，按入口回退 |
| P05 最小独立插件交付 | AppBoot/Loader 上的官方受控包交付薄层；自己的暂存/完整性/登记/安装事务与重启回退；V04 安装恢复、V04a 同格式不同 adapterId 独立插件接入证明 | 不建市场/自动更新/任意热卸载；样例只证明契约合规，不称真实第二 PDF 引擎 |
| P08 PDF 实际边界 | 从主体及独立 PDF 实际产物验证代码、传递依赖、原生运行时、资源和许可闭包；现有支持路径不因拆包无意破坏 | 不仅移动目录；不预先实现 MinerU 产品化；未过相关包门禁时不交付该包，不恢复旧附件 |
| Q01–Q03、Q04 必要部分与共用安全 | 快照受理、失败任务/产物释放、参数错误、必要文档元数据；D01/D03 中退出 drain、取消、worker 归属/清理、监听与重连的共用部分 | 不将共同风险推迟到桌面；旧归档 #30 索引整理后置；范围外历史主题按原条件处理 |
| npm 就绪准备 | [就绪清单](npm-readiness.md)覆盖包身份、实际归档、安装入口、使用说明、版本兼容和安全/许可证检查 | 保留 private:true，不安排 registry 上架、不创建凭据、不发布；发现阻塞进入对应 Q/P 包验收 |

P01 的基线回归与候选迁移分开提交；候选在本阶段前段通过后，依赖其语义的装配和独立插件才以该版本为目标。Q01/Q03、纯领域草案、闭包盘点及同 SHA 构建缩减可并行。若候选不通过，明确选择经测旧组合继续主链，不长期挂起所有基础工作。

## 放行证据

0.1.0 至少通过 V01–V04、V04a、旧数据/冻结/当前支持能力回归和所交付产物的闭包检查；这些是[验证矩阵](../0.1.x/validation.md)的切片，不另建通过状态表。V04a 必须在冻结主体上实际安装两个同格式不同 adapterId 的合规插件，缺席/禁用/错误/卸载后旧记录可读，新增插件只改包、配置及其测试文档。

完整 MinerU 流程和真实第二引擎的 V05/V06 留在 0.1.1；不能用 V04a 的合成数据或样例替代它们，也不能以它们尚未完成否定已通过的基础接口合规。跨引擎 PDF 重建继续独立验收。

没有发布日期和 npm 上架排期。最终候选元数据、来源提交、兼容矩阵及未交付能力必须可区分；历史 0.1.0 证据保留时点，不能拿旧 tarball smoke 代替拆分后的实际安装验收。
