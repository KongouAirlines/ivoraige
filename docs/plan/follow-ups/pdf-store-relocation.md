## 问题与影响

PDF 导入把受管理副本放在数据库旁的 `pdf/sources/`，但 `sourceBinding.sourcePath` 持久化为绝对路径。`PdfRuntime.rebuild()` 直接用该路径校验和读取原件。现有测试确认相对 store 输入仍保存绝对原件路径；若用户把数据库及旁边的 `pdf/` 目录一起搬到新位置，旧绑定仍指向原位置，冻结 PDF 导出可能失败，或在旧位置尚存在时读取旧副本。指南只要求同一 store 重启，当前未承诺可迁移；这是迁移场景的潜在限制，不是 PR #7 已验证的同路径重启回归。

## 处理条件与范围

本次 PR #9 处理设置窗口，不修改 PDF 持久化格式。用户需要备份恢复、目录搬迁或打包迁移时重新评估；届时确定相对路径绑定、存储根标识或受控迁移的边界，并检查旧记录兼容与路径逃逸风险。开始前核对 PDF 实施分支及新的验收需求。

## 验收条件

- 在新目录复制数据库及受管理 `pdf/` 内容后，冻结 PDF 输出从新根目录读取正确原件，不依赖旧路径。
- 已有绝对路径记录具备明确的兼容或迁移行为；丢失和篡改仍被拒绝。
- 三入口及三平台安装包场景下，路径处理与源文件所有权有实际验证。
