## 问题与影响

`Records.update()` 每次更新均对整个文档执行 `assertJson` 和 schema 校验，包括只更新任务进度的情况。既有合成数据局部探针表明长文档存在重复遍历成本；测量数值与局限保留在实施记录，不将其当作端到端性能承诺。

## 处理条件与范围

当前未安排实施。长文档性能成为阶段目标或实际使用瓶颈时重新评估；不能只因存在探针差值就删除校验。

评估在导入和持久记录读取边界保留完整校验，内部受控更新仅校验变更部分。固定版本 DSH 写入路径未重复执行同样的 schema 校验，JSON 可序列化及适用性／并发检查仍须保留。开始前明确受控更新边界；每文档聚合写入成本单独评估，不自动扩大为存储重构。

## 验收条件

- 非法输入拒绝、重启读回、修订与断点原子提交继续成立。
- 适用性、并发检查与 JSON 可序列化保证保留。
- 用同一长文档对照记录更新时间和分配量，说明环境、方法与局限。
