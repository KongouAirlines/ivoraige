# 后续功能与暂缓事项

集中记录实施过程中发现、尚未纳入当前阶段的功能建议和优化事项。本清单不是已承诺的排期，也不替代 [v2.0 设计](../requirements/v2.0/01_design_v2.0.md) 或 [当前实施记录](0.1.0/README.md)；既有设计中的计划能力继续按原里程碑跟踪，不在这里重复列举。

## 记录约定

每个条目注明状态、提出背景、建议范围、暂缓原因、开始实施前的决策和验收条件。状态使用“待评估”“暂缓”“已纳入阶段”“已完成”；纳入阶段或完成后补上实施记录／PR 链接，保留原条目以便追踪。

功能建议随提出它的开发分支维护，合并前不视为主线已接受的范围。兼容性边界与当前已实现行为仍写在对应功能文档中。

## 条目

条目按提出顺序记录；编号只用于引用，不代表优先级。

### D-001 完整 Quarto／QMD 支持

- 状态：暂缓，待评估；2026-10-06 用户明确要求作为后续功能考虑。
- 背景：当前 Markdown 适配器原先拒绝 YAML front matter。本分支已修复头部保留；用户论文的头部只读验证通过，但正文的 Quarto 引用仍触发 `reference or malformed link/image`。详见 [Markdown 当前边界](0.1.0/markdown.md) 和 [实施记录](0.1.0/README.md)。局部 YAML 兼容不代表整篇 QMD 可导入。
- 建议范围：接入 `.qmd` 的文件识别与各入口导入；明确支持的 Pandoc 引用、交叉引用、块／行内属性、带编号数学、图注、代码块与可执行单元等语法。所有语法绑定、引用键、编号和资源路径应在翻译／导出中保留；外部图片、bibliography／CSL 等资源须有明确的收集或缺失处理规则。
- 暂缓原因：这些能力需要统一处理来源绑定及资源，超出本轮 YAML 头部兼容修复；不能只放开扩展名或逐个忽略报错就声称完整支持。
- 开始前的决策：界定“完整支持”的语法及资源矩阵，评估复用现有 Quarto／Pandoc 解析能力；决定元数据中的 title／abstract 是否可译及其重建方式。默认不执行文档代码、渲染命令或 YAML 配置；如需执行，应单独设计并获得明确授权。
- 验收条件：用原创 QMD 覆盖语法矩阵，完成导入 → 翻译／人工接受 → 冻结导出 → 重启读回；未翻译内容可原样重建，译文输出保留语法与引用关系，资源缺失有明确反馈。CLI／HTTP／WebUI 共用同一内核结果，导出无追加模型调用。真实论文只读验证、不提交原文，失败项如实记录。
- 实施阶段／PR：尚未排期。

### D-002 多模型协作的模型标签与角色设计

- 状态：暂缓；2026-10-06 用户明确要求在多模型协作阶段再设计。
- 背景：当前模型设置可保存多个提供商／模型，并独立选定一个翻译模型；这些记录是配置，不代表协作角色或自动调度规则。
- 建议范围：在多模型协作场景确定后，设计标签、角色及模型引用方式，使模型可用于初译、审校等明确步骤；讨论标签作用域、重名规则及配置变更后任务的引用行为。
- 暂缓原因：协作流程和任务级模型选择尚未实现，提前设计标签会把未经验证的角色固化进配置。
- 开始前的决策：标签与稳定配置标识的关系、角色到模型的绑定、任务快照／恢复及调度规则。多模型不能绕过已接受译文的复用规则，导出仍不得调用模型。
- 验收条件：协作模型可追踪到具体配置及调用来源，重启／恢复保持任务绑定，配置变更行为明确，翻译调用和成本如实记录；标签改变不隐式重新翻译或覆盖人工接受版本。
- 实施阶段／PR：尚未排期。

### D-003 提供商在线目录与连接管理

- 状态：待评估。
- 背景：当前提供商预设与内置模型候选来自固定版本 pi-ai 目录；自定义端点填写模型 ID，不能确认账号可用性或本机加载状态。
- 建议范围：显式刷新提供商模型目录、本地服务模型发现、连接测试和配置删除／停用；评估是否直接复用上游 DSH 新能力。各提供商目录协议、认证及失效规则分别处理。
- 暂缓原因：网络发现和配置生命周期需要额外错误处理与任务引用策略，超出本轮保存／切换体验修复。当前用户仍可手动维护模型 ID 与端点。
- 开始前的决策：远程请求时机、缓存与过期规则、调用预算、失败时保留的已有配置，以及删除被任务引用的配置时的行为。
- 验收条件：目录失败不丢失已保存配置、不影响已接受译文；连接测试明确是否产生模型请求；任务在配置停用或删除后有确定的暂停／恢复行为。
- 实施阶段／PR：尚未排期。
