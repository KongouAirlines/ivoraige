# 0.1.x 工作包与依赖

每行对应一个可审阅 PR 的起点，过大时按该行验收再拆，不能合成整库重写。代码、定向测试、契约和受影响用户文档同 PR 更新。状态只在下表维护；旧 follow-up 状态仍在原文件，关系表只引用。这里的“草案”表示尚未实施；计划分支不占用生产实现任务。

主链为 P01 → P02 → P03 → P04 → P05 → P06 → P07。P08 与桌面基线独立推进，不把重建质量或远期 UI 管理作为纯解析的前置。P02 的 schema 改动和 P03 的 Records 编排迁移顺序提交，避免两个实现者同时重写 Records。P04 统一协议注册及事件，桌面只消费其接口。

P01 先在现有固定 DSH/Cordis 上交付闭包盘点和行为探针；同 SHA 的获取/构建缩减可独立切 PR。候选运行时升级与公共 DSH 组件包替换另行切分，在采用新语义或 P05 兼容范围定案前按[顺序评估](runtime-sequence.md)复评，不是 P02–P07 的统一前置。候选未成熟可继续经测旧 pin；真实阻塞缺陷用最小修复或经验证升级处理。不得把“获取较少源码”“发行分包”和“公共组件替换”当成同一完成条件。

Q01/Q03 是可先行的小修复，Q02 收口资源释放后接到 P04；Q04 不授权批量改写历史证据或自动关闭旧事项。全部 [75 个审计主题的去向](audit/README.md)已关联：`audit:D01` 等审计组与本表 D01 桌面工作包不同，引用时带命名空间。
