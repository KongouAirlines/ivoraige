# 0.1.x 工作包与依赖

每行对应一个可审阅 PR 的起点，过大时按该行验收再拆，不能合成整库重写。代码、定向测试、契约和受影响用户文档同 PR 更新。状态只在下表维护；旧 follow-up 状态仍在原文件，关系表只引用。这里的“草案”表示尚未实施；计划分支不占用生产实现任务。

主链为 P01 → P02 → P03 → P04 → P05 → P06 → P07。P08 与桌面基线独立推进，不把重建质量或远期 UI 管理作为纯解析的前置。P02 的 schema 改动和 P03 的 Records 编排迁移顺序提交，避免两个实现者同时重写 Records。P04 统一协议注册及事件，桌面只消费其接口。

P01 先在现有固定 DSH/Cordis 上交付闭包盘点和行为探针；同 SHA 的获取/构建缩减可独立切 PR。候选运行时升级与公共 DSH 组件包替换另行切分；本阶段优先在旧基线探针之后、依赖新语义的接线之前完成有收益且门禁通过的配套迁移，在采用新语义或 P05 兼容范围定案前按[顺序评估](runtime-sequence.md)复评，不是 P02–P07 的统一前置。候选未成熟可继续经测旧 pin；真实阻塞缺陷用最小修复或经验证升级处理。不得把“获取较少源码”“发行分包”和“公共组件替换”当成同一完成条件。

Q01/Q03 是可先行的小修复，Q02 收口资源释放后接到 P04；Q04 不授权批量改写历史证据或自动关闭旧事项。全部 [75 个审计主题的去向](audit/README.md)已关联：`audit:D01` 等审计组与本表 D01 桌面工作包不同，引用时带命名空间。

候选版本按[交付范围](releases.md)取本表的可验收切片，执行状态仍以本表为准。0.1.0 至少包括基础链 P01–P05、P08、W01 及所交付能力的 Q/D 共同安全部分，V04a 证明独立插件契约，W-V01 证明真实组合；真实引擎的 P06/P07/P09 与桌面专属部分分别后续验收，不提前标记整个工作包完成。

W02 紧接 W01，W03 与其分切片衔接，不等待 D05 或 W04；完整可保存组合不因高级图形交互后置而无限推迟。F01/F02 优先窄范围，F03/F04 独立后续；I01 先通用契约和 Zotero 首片，I02/I03 后续择取候选。格式和协作不等待完整工作流 UI、MinerU 质量对照或原生桌面，详见[支线路线](formats-integrations.md)。

U01 独立页不等待 W02/W03/W04 或桌面，转项目在 W02 就绪后衔接。U02 按导航/设置、模型与连接、插件管理分别切 PR；U03 按术语、存储、预检分交付，避免一个管理界面 PR 包揽全部能力。后端 P05 不等于管理 UI 完成。详细归属与要求追溯见 [UI 草案](../../requirements/0.1.x/ui.md#要求与交付映射)，验收案例集中在[验证矩阵](validation.md#独立普通翻译与管理-ui)。
