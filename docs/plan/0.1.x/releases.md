# 0.1.x 候选交付范围

这是内容分期，不是发布日期、npm 上架安排或“已实现”声明。执行状态只在[工作包表](work-packages.md)，每个实施 PR 仍需代码、测试、契约和使用文档一起更新。

## 版本身份

仓库 package.json 当前已经是 `0.1.0`；既有 [0.1.0 实施记录](../0.1.0/README.md)和历史 GitHub tarball/Windows/PDF 证据按原时点保留。新 [0.1.0 基础候选](../0.1.0/foundation-plan.md)是这一轮待完成的基础体系范围，不重写旧记录，不恢复或覆盖历史 Release。此前 GitHub 上的 npm 格式 tarball 附件不等于 npm registry 发布。

本表的版本是候选目标；包名、registry 中版本可用性及发布权限尚未核实。未来如实际 registry 版本已占用，选择新的可用版本并更新计划，不覆盖已发布版本。宿主、插件、Host API、数据/快照 schema、sidecar 协议、外部引擎版本分别维护；拆分 PDF 插件不要求其版本机械跟随宿主。

## 范围与放行条件

| 候选 | 内容与工作包切片 | 明确后置 / 放行条件 |
| --- | --- | --- |
| **0.1.0 基础体系** | P01–P05 最小闭环、P08 实际 PDF 分发边界；Q01/Q02/Q03 的发布安全问题及 Q04 必要元数据/兼容说明；D01/D03 中共用 host 退出、取消、状态同步/监听清理，不含原生壳。npm 就绪准备单独验收 | 旧记录/修订/冻结输出与当前支持路径保留；V01–V04 及独立同格式、不同 adapterId 插件的 V04a 合规证明通过；风险和未测项收口。没有 npm 日期或上线动作 |
| **0.1.1 引擎产品化** | P06 MinerU 无翻译纯解析、P07 第二真实同类插件、P09 同译文 PDF 质量与重建；按实际引擎补齐 P08 资源/许可闭包 | V05/V06 和质量矩阵独立完成；样例插件不替代真实第二 PDF 引擎。P10 跨引擎映射继续独立实验，失败不挡已通过的纯解析或同引擎路线 |
| **0.1.2 桌面体验** | D01–D05 尚未交付的桌面专属部分：原生托盘、可销毁 UI、草稿日志/恢复、worker 空闲策略、定向 UI 刷新与原生验收 | 依赖基础宿主/事件和稳定任务接口，三平台 native 与资源预算实测后放行；不以内核 CI 代替原生验收 |

这是按依赖和风险切片，而非把整个 P/D 编号强塞进一个版本。某切片移到后续版本时要指出未完成边界及受影响能力，不能把“基本完成”当作对应包已全部验收。项目完整管理、术语/风格完整界面、漫画/超分与完整服务配置管理仍不由这些候选版本号自动承诺。

## 跨版本不允许后移的风险

数据/配置兼容、任务与冻结快照一致性、退出先停业务后关库、缺件可诊断、恢复通道、凭据/私有样本不进入包、实际分发闭包与许可，属于所交付产品的共同风险。凡 0.1.0 已提供的 CLI/HTTP/MCP/WebUI 或 PDF 路径涉及这些风险，须在 0.1.0 收口，不能以“桌面放到 0.1.2”推迟。

D04 当前 host/browser 的资源与故障基线可以提前开展；原生托盘/GPU/可销毁 UI 的体验预算留待桌面实现。未交付自动销毁窗口时无需提前实现完整 DraftJournal，但现有保存与任务恢复必须诚实描述、验证，不能宣称崩溃可恢复未保存编辑。
