# 0.1.x 候选交付范围

这是内容分期，不是发布日期、npm 上架安排或“已实现”声明。执行状态只在[工作包表](work-packages.md)，每个实施 PR 仍需代码、测试、契约和使用文档一起更新。

## 版本身份

仓库 package.json 当前已经是 `0.1.0`；既有 [0.1.0 实施记录](../0.1.0/README.md)和历史 GitHub tarball/Windows/PDF 证据按原时点保留。新 [0.1.0 基础候选](../0.1.0/foundation-plan.md)是这一轮待完成的基础体系范围，不重写旧记录，不恢复或覆盖历史 Release。此前 GitHub 上的 npm 格式 tarball 附件不等于 npm registry 发布。

本表的版本是候选目标；包名、registry 中版本可用性及发布权限尚未核实。未来如实际 registry 版本已占用，选择新的可用版本并更新计划，不覆盖已发布版本。宿主、插件、Host API、数据/快照 schema、sidecar 协议、外部引擎版本分别维护；拆分 PDF 插件不要求其版本机械跟随宿主。

### 新增支线的阶段安排

0.1.1/0.1.2 是此前引擎/桌面范围候选，并非已经冻结的全部发行顺序。以下新阶段按依赖、优先级安排，具体补丁版本待验收切片后分配，不把全部功能机械塞进这两个版本，也不约定日历日期。

| 阶段 | 优先内容与前置 | 不作为前置的工作 |
| --- | --- | --- |
| 紧接基础的可保存组合 | W02 在 W01 后交付增删/替换操作、输入选择、保存/另存/版本化、目标输出及局部重跑；W03 衔接内容主区与卡片/侧栏 | 不等完整桌面、多项目共享管理或自由拖拽图；真实组合保存不得无限延期 |
| 格式优先支线 | F01 DOCX、F02 无 DRM 可重排 EPUB，从提取/草稿到窄范围原生输出；依赖 P02/P03，独立包按 P05 | 不等 MinerU 重建质量、高级工作流图或原生壳 |
| 软件协作优先支线 | I01 通用交接契约与 Zotero 选择附件导入 → 任务 → 显式新产物回挂，依赖 P04/P05 | 不等旧四模式/RAG/双语 PDF 全部交付 |
| 后续独立扩展 | F03 PPTX、F04 XLSX；I02 固定客户端的网页/OCR入口、I03 笔记与电子书文件交换；W04 高级图编辑 | 每项以实际能力和样本决定范围，不承诺候选名单全部交付 |

格式层级及软件候选依据见[路线](formats-integrations.md)，工作流的冻结/可变边界与内容交互见[设计](../../requirements/0.1.x/workflows.md)。这些阶段仍不安排 npm 发布。

这是按依赖和风险切片，而非把整个 P/D/W/F/I 编号强塞进一个版本。某切片移到后续版本时要指出未完成边界及受影响能力，不能把“基本完成”当作对应包已全部验收。完整共享项目/多库管理、术语/风格完整界面、漫画/超分与完整服务配置管理仍不由这些候选版本号自动承诺；W02 最小项目绑定与可保存流程有独立交付边界。

## 跨版本不允许后移的风险

数据/配置兼容、任务与冻结快照一致性、退出先停业务后关库、缺件可诊断、恢复通道、凭据/私有样本不进入包、实际分发闭包与许可，属于所交付产品的共同风险。凡 0.1.0 已提供的 CLI/HTTP/MCP/WebUI 或 PDF 路径涉及这些风险，须在 0.1.0 收口，不能以“桌面放到 0.1.2”推迟。

D04 当前 host/browser 的资源与故障基线可以提前开展；原生托盘/GPU/可销毁 UI 的体验预算留待桌面实现。未交付自动销毁窗口时无需提前实现完整 DraftJournal，但现有保存与任务恢复必须诚实描述、验证，不能宣称崩溃可恢复未保存编辑。
