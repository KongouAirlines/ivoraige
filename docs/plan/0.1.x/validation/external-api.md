# 可调用方案与外部协议验证

这是 [I-V01/I-V02](../validation.md#i-v01) 的专项案例，W-V02/W-V03 复用其中冻结和管理部分；不新增顶层工作包或进度源。需求见[外部 API](../../../requirements/0.1.x/external-api.md)，切片见[路线](../external-api.md)。每个交付记录精确提交、协议/方案/词库/抽取版本、客户端构建、合规样本、命令/操作和实际失败结果；未运行案例明确列出。

基础门禁引用 [I-V01.shared](formats-integrations.md#i-v01-shared) 的全部 HTTP/MCP 授权拒绝用例、[I-V01.callable](formats-integrations.md#i-v01-callable) 的无管理 UI 发布路径及 [U-V03.terms](ui.md#u-v03-terms) 的真实后端证据。记录具名 @1 子契约的实现版本；本页追加 wire/客户端案例，不重写基础判据。

## 方案与原生调用

- 同一保存定义发布 r1，修改草稿和全局模型/词库默认不影响 r1；发布 r2 后新运行取 r2，在途和历史仍是 r1。指定旧修订需仍有授权；撤回后不再受理新运行，缺模型/词库/插件返回确切 unavailable。
- 同时运行两个不同模型/术语方案与同方案不同允许覆盖；有效绑定不串，公共实现无全局模型切换。UI、原生、MCP 和 OpenAI 适配的同一输入/修订解析为相同有效约束，随机模型文本无需逐字相同。
- 单项、乱序完成批次、重复/缺失/额外 ID、空项、超限、部分失败和结果读取逐项验证；结果保持输入 ID/顺序。JSON 样式原文不被误解成协议，非法覆盖在模型调用前拒绝。
- 同一主体幂等键同内容返回原 runId，发布更新后重试仍读原修订；异内容冲突，另一授权域不能读原结果。记录保留期与过期行为；网络断开/超时后先查结果，不盲重试未知收费。
- 原生、HTTP-MCP 与 OpenAI 在各自连接方式重跑 I-V01.shared 拒绝矩阵，按[协议映射](../../../requirements/0.1.x/external-api.md#协议授权映射)核查 scope；尤其已撤销令牌的流重连/幂等键不能再取历史结果，无效 token 为 401，有效主体越权为 403，获准范围内缺对象为 404。未知服务身份需确认；URL 不触发隐式抓取。
- 同形术语在两来源下先筛适用性再看优先级；中央库与请求 glossary 冲突默认可见，允许覆盖只限本次和允许字段，锁定条目不变。抽候选、本次使用和确认入库分开；修改约束版本使相应复用失效，旧接受与快照保留。继续通过[术语双来源基线](cross-cutting.md#术语与复用)。
- 取消、超时、缺件及重启沿用任务契约；请求取消、实际停止与供应商执行未知分别记录。HTML 标签/占位符安全保持，脚本/外链不执行。解析、译文忠实/漏译/术语一致性与 HTML 重建分别评分，沿用[质量分层](cross-cutting.md#质量分层与译文评审)，不只检 HTTP 状态。

## 管理和跨入口一致性

以下管理 UI 案例属于 W03.publish-ui@1，后于 I-V01.callable 的 owner CLI 验收。禁用全部管理页面时，原生/KT 的获准调用仍可完成；该证据不得等 UI 交付后再补。

- 从软件联动与保存工作流入口打开同一方案管理器；保存/复制/参数编辑/测试/发布/撤回可由键盘完成，未交付能力不呈现假菜单。模型、词库及全局运行策略仍各归其管理页。
- 显示草稿/发布差异、实际词库/抽取版本、目标语言、锁定及允许覆盖字段；测试前说明本次输入、外发和费用，取消保留真实结果。两个窗口发布同一草稿发生冲突时不覆盖对方修订。
- 普通翻译和无项目客户端调用不被强制建立长期项目；从模板先保存同一模型的实例修订，RunDefinition 仍引用它，输入/结果只能由其所属授权域读取。已保存流程无需 W04 或原生桌面即可管理。撤回/禁用后旧历史可读，恢复所需版本缺失时给修复入口，不能暗换配置。

## OpenAI 兼容

- 固定一个实际客户端及其版本，明确 plans.read / runs.create / runs.read 及按需 runs.cancel 的授权；模型列表只含授权、已发布、输入/语言兼容的方案，真实模型及人工等待/二进制流程不可见；方案不可用的展示/执行结果一致。
- 测单 user 文本、允许/禁止的 instructions、固定/覆盖目标语言、未知参数、n 非 1、多轮/工具/图片、真实模型 ID 冒充方案及越权覆盖。明确拒绝与声明的映射一致，不能只检查路径或 200 响应。
- batch-json 仅在显式 profile 下解析；纯文本中的 JSON/提示词不被当作控制参数，批次 ID 完整。原生结果存在部分失败时不包装成成功译文。
- 非流式与流式完整结果一致，流前的术语/结构检查可改草稿但已发最终内容不可回写；截断、取消、上游错误不能生成成功终止。验证终止 chunk、`[DONE]` 和未知 usage 处理，日志/结果能追踪原 runId。
- 已知 usage、部分阶段未知和完全未知分别验收；缺失不填 0，多阶段统计口径清楚。遇客户端不能接受 null/省略时标具体兼容限制，不伪造计费。文档列出已测子集及未支持项。

## KT 实际集成

KT 与 Zotero 同级高优先，以下案例可与[Zotero 验收](formats-integrations.md#i01)并行准备和执行，不设客户端完成顺序。契约/适配探针可先并行联调，端到端通过证据必须引用 I01.shared@1 / I01.callable@1 与 U03.terms@1 实现版本及对应通过记录；KT 原生路径不以 OpenAI、I01.zotero@1 或 W03.publish-ui@1 通过为前置。

- 记录支持接口插件的 KT 精确版本/SHA、浏览器、SDK、插件包摘要；实际从目录/ZIP 安装、授权固定 origin、配置连接和选择方案。未验证商店版不写“商店用户均可用”；更新模板、旧实例升级、撤权和卸载分别验证。
- 单段、single/text 与 batch/json 等实际声明模式、HTML 标签与占位符、多段乱序、重复/缺失 ID、空译文分别测试；不能只处理第一项或按数组位置回填。
- 同一合规样本对照 KT 原有术语替换/Playground 和中央方案；记录 KT 替换引擎开关及顺序，检查双重替换、冲突和同形异义。证明共享配置/版本带来的效果，不以“KT 无术语库”作成功基线。
- 有/无 title、URL、glossary、有限 context 的行为可解释；片段抽取只产生片段范围候选，全文依赖方案在缺全文时拒绝或按明确 profile 降级，不自动抓 URL。
- 调用中取消、Worker 终止、权限撤销、流缺终止、服务重启和结果恢复；不能捕获失败后返回空成功，也不能把未送达 cancel 当停止。发布包不含凭据/个人路径；无需 fork KT 或暴露全部内部 API。

真实外发和模型调用使用获准的小型公开/合成样本；本规划的静态检查不构成任何一项运行验收。
