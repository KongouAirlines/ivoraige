# 0.1.x runtime candidate comparison (2026-10-23)

Decision: **retain the DSH `639ed015` pin**. The only reproducible candidate from DSH's default branch, `687f282`, still vendors the same Cordis Core, Loader and Include source commits and fails the project's credential-free model preset contract. Updating the DSH number alone would add dependency and AppBoot migration work without obtaining the later upstream Cordis fixes. This is an isolated comparison, not a selected runtime migration.

## Executed comparison

The comparison was run in `ivoraige-runtime-candidate`, an isolated local clone, with the foundation checkout read only. The candidate was fetched at exact SHA, `scripts/setup-dsh.mjs` was temporarily pointed to that SHA, and `npm install @earendil-works/pi-ai@1.1.0 --save-exact --ignore-scripts --no-audit --no-fund` was run **only in the candidate checkout**. The new pi-ai npm artifact declares MIT but omits a license file; its [upstream MIT notice](https://github.com/earendil-works/pi/blob/main/LICENSE) matches `scripts/licenses/0.1.0/pi-MIT.txt`, so a temporary `scripts/build.mjs` fallback entry for `1.1.0` was required for the bundle. Candidate `npm run build` then passed. Before those two changes, the build failed first on missing `getAllBuiltinModels`, then on the missing verified notice. This is required migration work, not a passing result from changing the DSH pin alone.

For reproducibility, build each isolated checkout and run `node scripts/probe-runtime-candidate.mjs <pinned-checkout> <candidate-checkout>`. It checks the actual build evidence and executes the same six runtime, settings, volatile-profile, component-entry and store-lifecycle test files in both checkouts. Both branches contain the final P01 guard commit; this branch changes only the candidate dependency and evidence. The final script output was:

```text
pin: DSH=639ed015... inputs=1003 pi-ai=0.87.1 exit=0; tests 55, pass 55, fail 0
candidate: DSH=687f282... inputs=1076 pi-ai=1.1.0 exit=1; tests 55, pass 54, fail 1
```

The final P01 guard alone passed **13/13** on candidate: missing optional services, injected consumer teardown before Records closes, partial activation failure and reopen, component/business quota interleaving with zero spurious model failure, one bounded deadline for nonterminal or unresponsive `jobs.wait`, and pause/cancel/close races at quota admission and deferral. A further candidate selection of Records/task checkpoint, settings lifecycle, and component tests passed **55/55**. The candidate AppBoot-backed model settings, volatile profile persistence/restart, settings pages, component entries and store lifecycle selection passed **41/42**; the sole failure was the model preset below. These checks do not claim all Loader/Include reload and failed-publication behavior: the project does not yet exercise a controlled package move/recovery matrix for P05.

The bounded full candidate suite (`node --test --test-concurrency=4 test/*.test.mjs`) on the first P01 guard revision finished **261/263**. One failure was `test/license-notices.test.mjs`, which asserted the old `pi-ai 0.87.1` heading; the candidate's `1.1.0` notice was present. The candidate branch now updates that expectation and the targeted license test passes. The material failure remains `test/model-presets.test.mjs`: after a DeepSeek preset is saved without credentials, `llm.listModels('deepseek')` returns `[]`, although the catalog has `deepseek-flash` and `deepseek-v4-pro`. Candidate DSH's `packages/llm/llm-pi-ai/src/adapter.ts` lines 295–302 now intentionally return an empty list on `MISSING_CREDENTIAL`. The test expects users to be able to configure catalog models before supplying a paid provider credential. A direct local reproduction confirmed the saved route and empty list, with no model call or network request. This requires a product/DSH compatibility decision and targeted fix before selection; the test must not simply be removed. The final P01 guard revision received the 13/13 and 54/55 focused reruns above. [Draft PR #47 CI run 39909485370](https://github.com/KongouAirlines/ivoraige/actions/runs/39909485370) then ran the complete 271-test suite on macOS/Node 24.22.1, Windows/Node 24.22.1, Windows/Node 26.12.1, and Ubuntu/Node 24.22.1: each job had **270 pass, 1 fail**, the same DeepSeek preset assertion. CI skipped package smoke after the test failure; the isolated local package smoke below passed.

Candidate `npm run smoke:package` passed: a 69-file tarball installed in isolation, with parsing, same-version reinstall and complete data backup, saved settings, frozen snapshot and original exports, MCP discovery/call, and static UI. This checks the actual package artifact for this candidate closure, but it does not cancel the model-preset regression.

No real user store, credential or paid model was used. Local fixtures and mock HTTP endpoints were used. The initial unrestricted full-suite run in the sandbox was interrupted after unrelated HTTP timeouts; the bounded authorized run above completed on the first P01 guard revision. The final baseline P01 branch independently passed 271/271 with four-process concurrency; the six-file script passed 55/55 against its built pin.

## Migration gate and ownership

Do not select `687f282` for P05 yet. A migration PR would need the exact DSH and pi-ai closure, license notice/test update, a resolution of credential-free preset discovery that preserves the product behavior, package smoke, and focused AppBoot/Loader/Include tests for patch reload, failed activation, rollback/recovery, async persistence errors, and package mapping. It must rerun Records, task, settings, entry and package tests on the **same candidate SHA**. Splicing RC.12 Core/Loader/Include into DSH `687f282` would create an unowned combination across three modules while DSH still carries local lifecycle and reload patches. That requires patch-by-patch reconciliation, build and product acceptance and an explicit maintenance owner; it is not a small pin update. No current result justifies carrying a private long-lived Core fork or rewriting the domain to accommodate it. P01 can continue on the existing pin.
