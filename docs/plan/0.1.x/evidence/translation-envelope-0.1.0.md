# 0.1.0 translation request envelope, stage 2B

Related: [issue #59](https://github.com/KongouAirlines/ivoraige/issues/59), following [stage 2A](translation-boundary-0.1.0.md). A completed model response that is entirely a JSON object (also inside one `json` or unlabeled code fence) with exactly `sourceLang`, `targetLang`, `effectiveContext`, `effectiveTarget`, and `sourceText` is rejected when its language fields match the request and its context and target are objects. The source unit is exempt if it is itself wrapper-shaped JSON, including fenced JSON, regardless of the languages inside that source. Other JSON translations and plain text retain the existing path. This is a deliberately narrow response-shape check, not semantic translation validation: partial echoes, translated field names, prose around JSON, and neighboring text contamination can still pass. The response text is never copied into the public task error.

The model boundary raises `UPSTREAM_FAILURE` with a fixed diagnostic marker. The task presents a fixed message and fails before `commitTaskUnit`; the current whole-task failure behavior remains, with no added retries or model calls. Existing stored accepted revisions and frozen snapshots remain untouched. The request wire shape, DSH stream, record schema, reuse rules, and `scientific-translation-v3` prompt identity are unchanged. Issue #57's local retry or keep-original continuation is still pending.

Local verification on Linux with Node 24.22.1 and pinned DSH: `node --test test/translation-model.test.mjs` passed 12/12. The local DSH HTTP mock sent one full request envelope to a fast task: one model request was counted, the task failed with a safe public message, no revision was present in SQLite before or after restart, and no retry was made. Separate local stream checks rejected plain and fenced envelopes and accepted ordinary JSON, plain translation, partial/mismatched envelopes, and wrapper-shaped JSON source text. `npm test` built the DSH and web bundles and passed 540 tests with 2 skips and 0 failures (542 total). These tests use mock responses; they do not prove real-model compliance.
