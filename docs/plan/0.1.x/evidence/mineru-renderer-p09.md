# P09 partial: MinerU same-engine frozen PDF replay

This branch adds an experimental PDF output adapter to the optional MinerU 4.0.10 source package. It is **not** the completed P09 comparison: the same accepted translation has not yet been run through BabelDOC and MinerU with page-by-page quality and cost assessment. It does not make MinerU the default, prove broad OCR/PDF quality, close the independent installation and license audit (P05/P08), supply a second source plugin (P07), or enable cross-engine replay (P10).

## Contract and safety boundary

- MinerU imports keep their own source identity. The PDF output adapter accepts only a `mineru` frozen binding. Source mode verifies the saved bundle and returns its original `source.pdf` bytes and digest without starting Python. Accepted-translation mode compares the frozen units, order, source text, translatability and exact locators against the saved MiddleJson/structured projection. Later edits cannot change an older snapshot.
- Only frozen `revision` decisions become replacements; `skip` and non-translatable units keep source content. The Python sidecar checks that each replacement identifies the saved page/block or a caption/footnote child position, has the exact original text, and affects **one plain text span**. Multiple or mixed inline spans, or structured Markdown that differs from its raw text span after escaping/styling, are rejected for PDF replacement, not guessed. Their source import and readable MD/JSON projection still work. This is a deliberately narrow replay subset. It cannot recover information the parser omitted or classified as an image/equation. Records imported before nested annotations were projected have no `projectionVersion` and are checked against their original v1 unit layout; new caption-bearing imports use version 2 without rewriting older snapshots.
- The source adapter verifies the owner-specific managed bundle and its file hashes. Python checks all inventory sizes and hashes again, validates `docvortex.middle` schema 2.0 and MinerU producer 4.0.10, and allows the renderer to resolve images only from inventoried, verified bytes. Unknown relative/absolute asset requests fail. Output goes to an owned temporary path, and Node checks the returned PDF bytes, size and digest. The existing sidecar termination boundary applies before cleanup. No translator/provider call occurs during export.
- Replay requires **DocVortex 0.6.21** as well as MinerU 4.0.10. The source parser itself only requires the pinned MinerU version. This is a tested version combination, not a complete transitive-dependency or cross-platform guarantee. The private protocol 1 `rebuild` request/response is documented in [§7.1](../../../requirements/v2.0/03_API-protocol_v2.0.md#71-握手与方法); BabelDOC's request is unchanged.

## Verification on original synthetic documents, Linux CPU/flash, 2026-11-09

The already prepared [source acceptance environment](mineru-source-p05-p06.md#live-local-mineru-source-acceptance-2026-11-09) used Python 3.12.14, MinerU 4.0.10, DocVortex 0.6.21, ONNX Runtime 1.31.1 and official ONNX model revision `358310b4f64b95f9fefc372ad899356e4111f376`. The final PDFium-based generator created a 3,473-byte selectable mixed PDF and a 137,186-byte image-only scan with zero extractable source characters. Both imported through the real sidecar.

The opt-in `scripts/mineru-render-live.mjs` accepted two **manually specified** revisions per document (English title → `合成研究笔记：节水作物`, `Abstract` → `摘要`), explicitly skipped missing accepted units, and exported PDF/MD/JSON from one frozen snapshot. Both newly projected table captions remained in the MD source projection; this run left them in the source language, rather than claiming a translated table. Source PDF exports equaled their input bytes. Real PDF outputs were 3,923 bytes for mixed and 37,174 bytes for scan. Each is one A4 page (`pdfinfo`), and `pdftotext -layout` recovered both Chinese revisions. After disposal/restart, the old PDF replay had the same SHA-256 digest, even after a newer title revision was accepted; the new snapshot produced different PDF bytes. The test asserted there were no translation tasks. A second local probe accepted manually written revisions for all natural units and also rendered both PDFs, but was not the retained acceptance script's fixed test.

Both retained outputs were rasterized with Poppler and visually inspected. Chinese title and abstract were legible, with no observed clipping on these pages; the two-column positions and scan's raster table were retained. English glyph spacing was visibly uneven, and the selectable PDF's table header was merged into the caption and printed very small. The scan's table was largely an image, not independently translated cell text. These are substantive output-quality limitations. Text extraction and a `%PDF` header alone would not establish visual acceptance. Neither sample supports a general claim about scanned scientific PDFs, formula integrity or consistent pagination.

A separate local probe accepted a manually written Chinese caption (`表1：虚构观察值`) in each new projection and invoked the real renderer after reopening. Both resulting one-page PDFs contained that caption in `pdftotext`, and Poppler page images showed it in the table-caption position without observed clipping. The selectable PDF's upstream caption had incorrectly absorbed header text; replacing that whole caption with the shorter Chinese phrase also removed the header from text output. This is a reason to inspect or correct the source before accepting a caption translation, not evidence of table fidelity. The probe's rendered files and PNGs are kept in the developer's ignored `evaluation/runs/mineru-renderer-v5-final/` folder, not in the release package.

Deterministic, model-free tests cover frozen selection after restart/edit, original PDF bytes without a runtime, changed/missing resources, locator mismatch, both caption and footnote revisions on one composite block, legacy projection replay, complex inline-span rejection and inventoried asset resolution/refusal. The Python guard test uses stub renderer modules: it proves the bridge's narrow boundaries, not real render quality. The real PDF observations above were made with the actual pinned MinerU/DocVortex environment. They do not exercise a packaged Windows or macOS runtime.

### Reproduce the local replay check

First deliberately prepare and verify the local Python/models and original synthetic samples as described in the [source evidence](mineru-source-p05-p06.md#reproduce-with-original-synthetic-inputs). The following script does not install, download or translate; it requires a **new** run directory containing `venv/bin/python`, `samples/mixed.pdf`, and `samples/scan.pdf` on Linux. It creates `render-acceptance/` beneath that run directory and refuses to overwrite an existing store:

```sh
RUN="$PWD/evaluation/runs/mineru-render-check"
export MINERU_HOME="$RUN/mineru-home" MINERU_MODEL_SOURCE=local MINERU_MODEL_SMALL_BACKEND=onnx
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
node scripts/mineru-render-live.mjs "$RUN"
```

Inspect `render-acceptance/report.json`, the PDF/MD/JSON exports and each rasterized page yourself. The script fails nonzero for incomplete imports/exports or digest changes. The test run and rendered files are intentionally ignored, not shipped in the npm package. The printed byte sizes are from the stated environment and can vary with fonts/library versions; do not treat them as a portable golden output.
