# Q02 resource retention and failed-task release evidence

Q02 is implemented on `codex/0.1.x-resource-retention`, stacked on P03 `9c22bd38df1153624eb232db47d1cc67422e2b87`. Branch validation does not complete P04 registration/event lifecycle work or merge the earlier draft PRs.

- A failed import, translation or export task can be explicitly moved to `abandoned`, preserving error/history and rejecting resume; failed `cancel` still rejects. An abandoned export task releases its resumable snapshot claim. Queued/running/paused tasks cannot be abandoned.
- Artifact record removal defaults to keeping bytes, including external `out`. A managed default export records SHA-256 ownership. Explicit `delete-owned` checks owner root, regular file, original bytes, other artifact paths, active/failed task refs, snapshot leases and download/resource read leases. Terminal task artifact checkpoints are removed in the same record update.
- Managed-file cleanup uses a durable per-document tombstone before unlink. A failed unlink retains path, digest, error and snapshot reference; list cleanup then retry by original artifact ID. In-memory path/snapshot reservations prevent intervening adoption; a backend-write gate proves an earlier same-path `addArtifact` blocks deletion even before that record is visible. Snapshot deletion reserves before storage commit. No simulated hard power loss or real user-store migration was performed.
- Affected documents move to `schemaVersion: 3` only on their first Q02 write. Synthetic v1 first-write and v2 unaffected-row tests pass; unknown 4/0/-1 writes reject. Old binaries cannot safely open or write upgraded records. Rollback requires a complete pre-write SQLite and file backup, not a code-only downgrade.
- CLI, HTTP and MCP expose the same explicit delete, cleanup-list and abandon operations. A real loopback entry test exercises each transport.

### Relocated export-root cleanup correction

A durable cleanup tombstone could remain pinned after restart if the former managed export root had been moved or removed: root validation preceded the missing-file check, so retry repeatedly returned cleanupPending even though no unlink was needed. A fixed-ad300df fixture reproduced the failure. Cleanup now treats ENOENT/ENOTDIR at the original artifact path as completed without touching any file; when a file remains at the old root, the current-root and digest checks still reject its deletion. The three relocated-root cases cover missing file, missing parent and still-present old file after an interrupted cleanup. Local targeted regression passed 13/13. After this correction, build passed at unchanged DSH pin `639ed015397290b3745d163aafe02ffee4aa3f84`; the complete suite passed 314/314 (`node --test --test-concurrency=4 test/*.test.mjs`), and isolated package smoke passed with 70 files. Loopback-dependent tests used the localhost-enabled environment. The prior fixed-head PR51 CI run 39936557248 completed successfully across all four matrix jobs before this follow-up commit; a new head requires its own CI.

### HTTP download lease correction

The original real-loopback probe observed a client disconnect while artifact `stat` was suspended: the HTTP handler had not yet installed its response-close listener, so the read lease remained held and record deletion returned `CONFLICT`. A copy with post-fix assertions now observes one release, no stream opened after the disconnect, and successful record deletion. The committed HTTP regression gates acquisition, `stat`, and stream opening independently, then checks stat/open failures and a complete response. Each path releases exactly once, leaves no artifact lease, and permits record deletion. The handler registers response-close cleanup before its first await and checks the closed state after every awaited stage. This is a lifecycle correction; no entry wire shape changes.

On this follow-up branch, the focused HTTP suite passed 8/8, the complete suite passed 322/322 (`node --test --test-concurrency=4 test/*.test.mjs`), build retained DSH pin `639ed015397290b3745d163aafe02ffee4aa3f84`, and the isolated 70-file package smoke passed. The original probe was not modified; only a temporary local copy was used for before/after expectations. No remote CI has run for this follow-up head.

Explicit `delete-owned` verifies the current managed root, file identity and digest before unlink and coordinates in-process references and leases. It assumes the managed output path is not concurrently replaced by an external process during that command; the check and unlink are not a cross-process atomic defense against a malicious local replacement. Default record-only deletion retains the bytes and does not depend on this physical-delete boundary.

### DSH SQLite unit-version fence

The Q02 record schema marker alone did not prevent a pre-Q02 binary from opening a store and stripping unknown cleanup fields on a later write. The DSH SQLite unit uses an exact `units.version` comparison before loading Records. New synthetic stores now start with `ivoraige_records` unit version 2. An existing version-1 store opens normally and ordinary writes leave that version unchanged. A validated first Q02 document or import-task transform synchronously stamps unit version 2 in a SQLite transaction before the DSH row put. A forced row-put failure leaves the old row unchanged but keeps version 2, so the older binary is fenced. On startup, a version-1 header with an existing Q02 cleanup/abandon payload is conservatively stamped 2 before opening Records; unsupported source IR or unknown header versions are rejected instead of blindly activating. No bulk row rewrite or new data location is involved.

Synthetic gate tests passed 7/7: embedding configuration, new/old stores, ordinary writes, invalid transform, first managed artifact, failed row put and restart, abandoned import, pending cleanup under an old header, unsupported IR and unknown domain version. A temporary cross-version probe imported the actual `8dc548d` old application from `task-2/q02-old-main` and observed `version-mismatch` when it opened a disposable version-2 store; the probe was removed and its path is not a test dependency. After the gate change, `npm test` built the unchanged DSH pin `639ed015397290b3745d163aafe02ffee4aa3f84` and passed 329/329. Isolated package smoke passed with 71 files. These checks used only temporary synthetic SQLite stores; no real user library was migrated. A full pre-write SQLite and export-file backup remains the rollback boundary.

### Cross-directory file-symlink reference correction

Comment6386882301 identified that the old key combined the alias parent directory with the canonical target basename, so a cross-directory file symlink did not count as a shared target reference. The corrected key resolves the complete target before identifying its parent and name; dangling targets fail closed for physical deletion. New tests cover same-document and cross-document references, default retain, final deletion/dangling behavior, ordinary case-sensitive/insensitive identity and missing-file metadata-only deletion. Existing root, digest, active/failed-task, lease, cleanup and unit-version guards are retained. On local Node26.12.1, Q02/domain/records passed38 tests with one file-symlink case skipped for Windows EPERM; directory alias and real HTTP/CLI/MCP tests passed. Initial restricted-shell directory EPERM and loopback EACCES logs were preserved as environment failures. Actual file-symlink execution must be confirmed in the Linux/macOS exact-head CI; this local skip is not acceptance of that scenario. Full head-specific suite/build/package/CI results are recorded separately. No real user file was touched, and the documented external concurrent-replacement boundary is unchanged.
