# #58 逐单位翻译提示词库实施记录

范围：在现有 `0.1.0` 内核加入可用的本地翻译提示词库，不声称改写、审校、术语抽取、项目设置或工作台编辑页已交付。对应[需求 #58](https://github.com/KongouAirlines/ivoraige/issues/58)。当前默认仅适用于 `ivoraige.translationModel` / `translate-unit`；其他插件功能可注册自身输入／输出契约及专属内置默认，不借用翻译模板。实现由共享 operation 提供 CLI／HTTP／MCP 管理入口，原有请求保持兼容，仅给 `translate` 加可选 `promptTemplateId`。

本地数据复用当前 DSH `StorageDomain` 所在 SQLite，而非引入并行 JSON 设置文件。模板每次编辑保留旧版本，绑定到模板 ID 并在新运行解析最新版本；任务处理第一个单位时保存实际选择，修订记录模板版本、有效内容摘要、来源、模型连接配置摘要与协议版本。有效内容摘要只取功能／输出约定和实际样式，不取 ID、名称、版本或创建时间，避免单纯重命名或同内容复制触发额外调用。首次写入新任务／修订字段前将 Records 域版本提升到 3，旧版读者被挡住，未使用提示词字段的旧库仍保留旧版本。连接身份包含 provider、model 和选中模型的路由／端点配置，不含凭据值。复用候选保留原有来源／约束适用性检查，并另检查机器修订的提示词及连接追溯；历史无追溯机器修订不会误命中新调用。现有冻结导出仍只消费修订，模板编辑不改写旧修订或快照。样式作为 `effectiveTarget` 数据，v3 必要 system 协议和回显拒绝规则保留在翻译服务中。

验证：本地 fake OpenAI-compatible SSE provider 与 SQLite 夹具覆盖默认无配置翻译、不同模型／连接及功能的绑定隔离、复制／编辑／恢复、文档与单次选择、丢失或不兼容模板、无插件功能、错误数据隔离、CLI 操作、版本追溯、编辑后重新调用和已有导出保持不变；仅重命名和同样式复制不新增模型调用，样式变化重新调用；合成旧读者测试验证首次单次选择和默认固定选择均在写入前挡住旧域版本，直接嵌入 Records 而无版本门禁时拒绝新增字段。没有付费模型调用。`npm test`：578 项中 576 通过、2 跳过；Node 24.22.1，使用现有 pin 的 DSH bundle。仓库默认 Node 26.13.0，仍需该版本的 CI 验证。

未覆盖：项目对象与配置界面尚不存在，不创建占位项目范围；其他功能需要各自插件交付实际调用和默认模板。当前回退仅在已绑定模板失效且同功能内置默认兼容时进行，显式本次选择报错；不对丢失插件做跨功能回退。跨工作区模板分享与提示词市场不在此切片。

后续边界回归：用两单位本地 fake SSE provider 保持第一个请求在途，先暂停，再把已绑定模板从 v2 改到 v3；第一个单位提交后 cursor 为 1，关闭并重启同一 store，续跑第二个单位。两个实际请求中的 `stylePreference` 均为 v2 的 `Original style.`，两个修订追溯版本也都是 2，任务保留 v2 选择。`npm_config_cache=/tmp/ivoraige-first-tier-npm-cache npm run smoke:package` 已通过：84 文件包在隔离安装下通过解析、同版本重装与完整数据备份、设置、冻结快照和原件导出、MCP 发现／调用以及静态 UI 检查。

DSH profile 组合验证：在真实 `bootModelSettings` 配置中由 `cordis.patch.yml` 加载本地功能插件，该插件声明 `inject=['ivoraige.prompts']` 并在激活时注册自身功能与专属默认模板。仅启动配置时，AppBoot 将它列为 `pending (waiting for service: ivoraige.prompts)`；`createApp` 稍后挂载 PromptLibrary 后，DSH 自动激活该 profile 条目，功能可列出且能解析它自己的默认模板。此 pending 警告不是永久禁用，也无需新配置平台。仓库测试使用临时 profile 和本地插件文件，不请求网络或模型。

DSH 对 PR #91 的审查指出 API 协议 §3.9 将未带 `promptTemplateId` 的旧请求误写为“直接采用内置翻译模板”，与已说明的文档／全局绑定优先级冲突。协议契约与用户指南现说明：旧请求无需新增字段，但适用绑定仍生效；无自定义绑定时才直接采用内置默认。双语 README 也已说明绑定与覆盖范围。上述 DSH profile 回归是独立的测试内容，用于验证晚挂载服务的真实激活行为。

msjs 对 PR #91 的审查指出，配置模型时过早执行术语装配预检，会使完整 basis 匹配且已接受的人工修订在零模型调用复用之前失败。现把连接／提示词解析与固定放在复用判断前，只在复用缺失后、模型调用计数前验证实际调用所需的 basis／术语约束。本地 fake provider 回归覆盖非 `none` 术语约束下普通及显式有效模板的人工复用、显式缺失／不兼容模板拒绝、无可复用修订的术语拒绝；均不发请求，调用计数为零。

DSH 对该增量的条件审查提出替换模型服务的提示词方法契约可能不完整。现有 `task-capabilities` 替换测试只要求旧插件实现 `translate`，且未声明提示词功能；该无提示词路径保持可用，并不代表旧插件支持提示词。提示词能力现明确要求已注册翻译功能的模型同时实现选择解析与 basis 预检，并返回完整模板和追溯；只实现其中一种或漏掉模板／追溯时，任务在固定选择、复用或模型调用前明确失败。无外部模型／网络的原生 DSH 服务替换测试覆盖旧 `translate` 服务、两种缺方法及两种不完整选择的服务，以及完整服务的固定选择和修订追溯。
