# 0.1.0 标识符下划线分行候选

分支 `fix/0.1.x-pdf-underscore-line` 基于 #80 的 `c273d36`，不包含 #73/#74 模型边界或 #79 工作台选择修复。

## 原创复现与窄规则

实际 BabelDOC 0.6.4 分行方法对原创字形 `X_Y`（字母同一基线、下划线视觉范围较低）生成 `[X,Y]`、`[_]` 两行，后续分组沿用该顺序。候选只为满足下列条件的 `_` 采用相邻字母的有效 y 范围参与原分行算法：

- 原 composition 中连续三个字符；两侧均为单个 ASCII 拉丁字母，不跨非字符结构。
- 三者横排、同一个明确 XObject、字体和完全相同的正有限字号，字框与有效范围有限且非退化。
- 横向位置递增，邻接间隙在 -0.15em 至 0.5em 内；左右字母有效中心高度差不超过 0.1em。
- 下划线中心至少低 0.2em、最多低 1em。更远的低位符号不拉回正文。

只改变这次分行计算的临时范围，不改字符、坐标、字体、render order，不全局排序。条件不满足时调用原方法；正常退出和异常均恢复实例/类方法。该规则是明确范围的兼容适配，不是通用阅读顺序算法，也不能保证所有公式或标识符。

## 捕获与回放

新捕获在 `captureConfig.underscoreLinePolicy` 固定 `ascii-base-v1`。捕获和冻结回放按同一标记启用规则；旧绑定缺少标记时继续原方法，不能用新代码假定旧绑定已纠正。需重新导入以获得新来源绑定。它与 `layoutFitPolicy` 独立，两种旧/新配置组合可回放，未知策略在引擎启动前拒绝。协议与绑定 schema 不变。独立 PDF 组件源码同时携带适配模块，仍须完整重建。
