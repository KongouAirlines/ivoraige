# P04 operation and entry composition evidence

P04 is implemented in [draft PR #52](https://github.com/KongouAirlines/ivoraige/pull/52) on [codex/0.1.x-operation-entries](https://github.com/KongouAirlines/ivoraige/tree/codex/0.1.x-operation-entries), stacked on [Q02 #51](https://github.com/KongouAirlines/ivoraige/pull/51), which in turn depends on the reviewed P03 #49. The DSH pin remains `639ed015397290b3745d163aafe02ffee4aa3f84` and Node 24.22.1 / 26.12.1 remains the supported baseline. This work does not select the independent runtime candidate.

## Activated contract

One `OperationCatalog` owns each operation's input/result schema, dependency requirements, handler and cancellation metadata. Core contributions group records/tasks, settings, components and discovery. `Operations.invoke` delegates to the catalog and preserves the v2 envelope. CLI aliases, REST aliases and the existing MCP names still delegate to those same registrations; generic `call OP --set JSON`, `/api/operations/OP` and `ivoraige_op_OP` are internal projections for contributed operations, not the complete stable external API in I01. The retained `parameters` export is a compatibility schema export, not another runtime router.

CLI, HTTP and MCP services own their invocation controllers, servers, transports and subscriptions. Entries can be omitted independently; help remains a bootstrap command. Host shutdown stops entry admission, cancels/drains request handlers, then closes resources/tasks/components before withdrawing Records/storage and releasing its owner lock. A handler that ignores cancellation, or a pending artifact file acquisition that misses its drain deadline, leaves storage open and reports failure; it cannot be treated as a completed shutdown. Resource shutdown tracks acquisitions before their first file await, waits for their cleanup, then closes opened handles; a later disposal retry can finish. Arbitrary third-party hot unload is not promised.

Records resolves exact stored unit/revision/task/artifact IDs. Entries no longer derive ownership by splitting or prefix-matching IDs. HTTP and MCP read artifacts through the common resource service, including the same optional size limit and Records read lease. The default artifact read limit remains unlimited for compatibility; the HTTP JSON body limit is 10 MiB and the browser file limit is 7 MiB to leave Base64/JSON overhead.

The event bridge projects Cordis notifications, including the pinned DSH's post-commit `domain/changed` and settings revision notifications. It does not send raw stored values, credential values, Context or services. Settings page events do not require Tasks. State snapshots contain public document/task summaries, setting revisions, capability descriptions and component task status; they do not pretend to be an atomic copy of workbench text bodies. Existing body queries continue through their owning services.

V03 uses subscription-first ready (`subscriptionId`, host `generation`, `scope`, `barrierRevision`), then a stable synchronous authoritative snapshot. The active subscription stays installed through refetch and application. Revisions at or below the applied snapshot are discarded; newer notifications trigger refetch. Buffer overflow, disconnect, changed generation/scope or unstable readers invalidate synchronization and require a new handshake. The browser's existing effect uses this helper; there are no new screens or UI features. No persistent event replay is claimed.

## Verification

- Catalog tests cover one schema/handler registration, owner disposal, missing capability, parse-only/settings-only compositions, result data-only checks and required core result fields, canceled/drained calls and the preflight/close race.
- Real CLI/HTTP/MCP parity covers contributed result, invalid input, cancellation, removal and discovery. MCP retains SDK discovery/transport ownership; its supported request-handler hook dispatches arguments to the single kernel validator so SDK error strings do not replace the public envelope.
- Controlled event tests cover real Records backend commit, DSH partial settings save, no-Tasks pages, ready/snapshot/refetch boundaries, delayed/duplicate/filtered notifications, generation/scope changes, overflow and cleanup. A final reentrant invalidation after snapshot application converges without another event.
- Resource tests cover IDs whose spelling has no owner prefix, mismatched URI document ownership, common size policy and a client disconnect while lease acquisition is awaiting. A file-stat barrier also verifies a missed resource drain deadline keeps Records and its store owner alive until acquisition cleanup and a successful disposal retry.
- The existing built browser bundle is exercised in jsdom for the ready barrier and a last invalidation during snapshot response. Existing dirty-draft and settings-navigation regressions remain covered. This is not desktop or real PDF acceptance.

The first complete integrated run passed 345/345 tests. After synchronizing Q02, `npm test` built successfully but its default local file concurrency produced one unchanged synthetic PDF cancel deadline failure (364/365); the exact targeted case then passed without changing its assertion or timeout. The earlier full suite at file concurrency 4 passed 365/365. The final acquisition-drain and required-result-field regressions increase that to 367/367, all passing at file concurrency 4 with no assertion or deadline changes. An intermediate overlapping run hit the unchanged synthetic PDF handshake deadline; that exact case passed alone. A later sandboxed run could not connect to local loopback (`EACCES`) and was stopped, then the complete final suite ran in the permitted local execution environment. The clean isolated package smoke passed with 81 files, including the unchanged DSH pin and built browser bundle. Two fixture adjustments were required by the activated boundaries: the jsdom window now exposes the browser `structuredClone` API, and the import mock returns the real accepted `taskId` field. Neither relaxed the corresponding assertion or product validation. The Q02 review fixes are synchronized, including its unit-version gate and early download disconnect cleanup. The compatibility facade keeps its own regression, while the common resource path has a real FileHandle.stat disconnect barrier. The actual 8dc old-main cross-check preserved the pending cleanup, refused the old writer with version-mismatch, and then let the new binary retry physical cleanup and release its snapshot. Exact remote-head CI (which runs the default test command) and the temporary stack-integration check are recorded with the PR.

## Remaining boundaries

Q02 activates the existing DSH SQLite unit-version gate before retention row writes, with no new runtime pin or data location. The synchronized regression confirms the actual older main 8dc548d refuses the activated store, preserves its durable cleanup and leaves the new binary able to retry and release the snapshot. Existing unit-1 ordinary reads/writes remain compatible; first retention activation requires the documented complete pre-write backup for rollback. The ownership/digest check for explicit physical deletion assumes exclusive use of the managed output path during the command and is not an atomic defense against another local process replacing that path between checking and unlink.

P05 package delivery, W01 workflows, external client authorization, all external APIs and real third-party PDF/desktop acceptance remain outside this change. The design-v3 follow-up stays in progress until accepted integration and its remaining scope is implemented.
