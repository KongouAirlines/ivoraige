## Activated contract

One `OperationCatalog` owns each operation's input/result schema, dependency requirements, handler and cancellation metadata. Core contributions group records/tasks, settings, components and discovery. `Operations.invoke` delegates to the catalog and preserves the v2 envelope. CLI aliases, REST aliases and the existing MCP names still delegate to those same registrations; generic `call OP --set JSON`, `/api/operations/OP` and `ivoraige_op_OP` are internal projections for contributed operations, not the complete stable external API in I01. The retained `parameters` export is a compatibility schema export, not another runtime router.

CLI, HTTP and MCP services own their invocation controllers, servers, transports and subscriptions. Entries can be omitted independently; help remains a bootstrap command. Host shutdown stops entry admission, cancels/drains request handlers, then closes resources/tasks/components before withdrawing Records/storage and releasing its owner lock. A handler that ignores cancellation, or a pending artifact file acquisition that misses its drain deadline, leaves storage open and reports failure; it cannot be treated as a completed shutdown. Resource shutdown tracks acquisitions before their first file await, waits for their cleanup, then closes opened handles; a later disposal retry can finish. Arbitrary third-party hot unload is not promised.

Records resolves exact stored unit/revision/task/artifact IDs. Entries no longer derive ownership by splitting or prefix-matching IDs. HTTP and MCP read artifacts through the common resource service, including the same optional size limit and Records read lease. The default artifact read limit remains unlimited for compatibility; the HTTP JSON body limit is 10 MiB and the browser file limit is 7 MiB to leave Base64/JSON overhead.

The event bridge projects Cordis notifications, including the pinned DSH's post-commit `domain/changed` and settings revision notifications. It does not send raw stored values, credential values, Context or services. Settings page events do not require Tasks. State snapshots contain public document/task summaries, setting revisions, capability descriptions and component task status; they do not pretend to be an atomic copy of workbench text bodies. Existing body queries continue through their owning services.

V03 uses subscription-first ready (`subscriptionId`, host `generation`, `scope`, `barrierRevision`), then a stable synchronous authoritative snapshot. The active subscription stays installed through refetch and application. Revisions at or below the applied snapshot are discarded; newer notifications trigger refetch. Buffer overflow, disconnect, changed generation/scope or unstable readers invalidate synchronization and require a new handshake. The browser's existing effect uses this helper; there are no new screens or UI features. No persistent event replay is claimed.

Focused operation, retention, entry, and live SDK tests cover these corrections; full-suite and package verification remain separate integration gates.

## Bound source-view contract correction (2026-10-28)

Reviews 5670026002 and 5670662603 exposed the missing provenance boundary on `510f6d703117228b74adc2a7b990e31f76ed87cb`. The first correction moved Parse-existence checks before admission; the second shared that check with discovery. Neither moved the actual adapter/version/schema/projection checks out of execution. Outputs received a binding without the document's pinned source implementation, and Records discovery, Tasks admission, direct Exporter and Parse execution could consequently disagree. This is why another service-presence patch would not close the defect.

Parse now owns a side-effect-free source-view compatibility check, reused by Outputs selection/discovery and projection execution. Records supplies document provenance; Tasks/Exporter supply current or resolved historical-snapshot provenance before all selected outputs are admitted. Software versions, source implementation versions and binding schema versions retain their distinct meanings. Snapshot binding-reference/resource-version checks and historical accepted revision choices are preserved; no stored schema or DSH change is involved. Required readable-text means a callable explicit projection; native Markdown remains the existing optional optimization. Projection execution and output rebuilding still consume frozen data without a model.

Global output formats mean installed capability, while binding/provenance-aware formats and document availableOutputs mean the stored document can pass structural preflight. Other healthy sources keep global MD/JSON capability available when one document's source is incompatible. Empty source registries cannot advertise view-dependent output. View-free binary remains available without Parse or a compatible source projection. Admission is a check of current state, not a registry lock: withdrawal after admission fails execution and retains the task's frozen snapshot for retry. Projection code throwing or returning invalid data remains an execution error; discovery does not execute arbitrary adapter methods.

The five source scenarios (restart without source, withdrawal, v1→v2, changed binding schema, same-version missing readableText) failed the bound-format assertion on the baseline. Corrected regressions cover Operations, Tasks, direct Exporter, HTTP and MCP, each with original/accepted text, new/historical snapshots, MD/JSON/mixed binary requests, zero snapshot-create calls/tasks/artifacts on rejection, binary success and compatible-source recovery. Additional tests cover queued withdrawal and same-snapshot retry, no projection execution in discovery, a frozen projection whose importer status is unavailable, and real HTTP capabilities/state alias parity. CLI PDF reopening now asserts no text formats without the bound source and successful discovery after restoring its configuration. The empty-Parse composition control now installs a real TXT source before expecting text output availability.

The independent sidecar investigation found an actual stdout/stderr ordering gap, not evidence that every reviewer failure was environmental. Existing diagnostics tests are unchanged; see [pdf-sidecar-stderr-diagnostic-order](../../follow-ups/pdf-sidecar-stderr-diagnostic-order.md) for the deterministic reproduction and remaining scope. Earlier reviewer/full-suite failures are retained above; successful runs do not prove this separate race absent.
