# P03 adapter contract and import coordinator evidence

This branch is a staged P03 implementation on P02. It is verified on a branch and awaits integration; it does not mark P04, P05 or any PDF subpackage complete.

Draft review: [PR #49](https://github.com/KongouAirlines/ivoraige/pull/49), based on the final P02 branch [PR #48](https://github.com/KongouAirlines/ivoraige/pull/48).

- `format` identifies a document or output type; `adapterId` identifies an implementation. Source descriptors declare supported formats, input kinds, version, binding schema and queue behavior. Tied matches fail rather than selecting registration order. A source must return a binding owned by its selected implementation.
- Importer owns parse-to-persist coordination. Records owns transactions, source IR, revisions and snapshots without mandatory Parse or Outputs injection. Translation-only compositions can omit Importer; import calls then return `COMPONENT_MISSING`. Read operations on existing records remain available if a source plugin is absent; human revision, model checkpoint and old-revision acceptance require the compatible private validator.
- Source IR resource identity stores `id`, `mediaType`, `contentDigest` and `version` without its location. The source binding retains private address and applicability data. Snapshots freeze the resource-version map and reject replay after a same-id content change.
- The established content fingerprint remains unchanged. Versioned source descriptors add an adapter id/version/binding-schema namespace to new document IDs, so a same-content reimport under a changed private implementation creates a separate document. Pre-P03 records without provenance retain their historical ID and deduplication path; the synchronous import task records the adapter used for the current parse even when that parse deduplicates to a legacy document.
- Output descriptors declare formats, binding/mode support and optional readable views. MD and JSON consume a normalized view; source-specific Markdown fidelity and PDF placeholder projection stay with their source adapters. Binary outputs do not require text projection. Renderers still receive frozen data, not a service object.
- Import tasks pin the selected source id/version. Export tasks pin selected output id/version at admission, recheck them on execution/resume, and record the actual id/version on artifacts. Missing or incompatible replacements fail explicitly. The direct Exporter compensates a newly created unreferenced snapshot if an adapter disappears before the frozen-stage check.
- The 0.1.0 PDF import wire response remains queued even if its optional component is absent; the resulting task reports the missing format. Direct Tasks imports still wait by default. Legacy TXT/MD/PDF paths are covered by regression tests.

### Selected-source scheduling correction

Under a real held Jobs quota, a high-score synchronous text source was incorrectly returned as a queued import when a lower-score queued text source also advertised the format. The unselected candidate had determined the wire wait policy, even though Tasks selected the synchronous source. Operations now delegates the wire response policy to the same Tasks selection that pins source id/version and import mode; direct Tasks calls still wait by default and an explicit `wait: false` still creates a queued task. A genuinely selected queued source remains queued, and the optional absent PDF component retains its legacy queued response.

The copied `task-2/retest-routing-expected.mjs` failed on the prior head with only `taskId`, a running task and zero parses; with only its import path and label adjusted, it passed with a `preferred-sync` document, succeeded task and one parse while quota remained held. The new regression waits for the actual quota-deferral storage write before asserting a selected queued task remains queued. It also covers an explicit queued source, a same-score ambiguity with no task, explicit disambiguation, and direct `wait: false`; existing PDF wire, binary output and frozen resource regressions remain active. The original review probe was not modified.

After this correction, the focused adapter/PDF/task-lifecycle suites passed 26/26, the full local suite passed 301/301, build passed at pinned DSH `639ed015397290b3745d163aafe02ffee4aa3f84`, and isolated package smoke passed with 70 files. ### PDF fallback input-compatibility correction

Independent review reproduced an input-kind omission at `d7b2baa`: registering a valid text-only PDF source suppressed the absent-component fallback for managed file paths and non-UTF-8 Base64. Those requests changed from an admitted task that later failed to synchronous INVALID_ARGUMENT. The same sibling also masked COMPONENT_MISSING from a compatible unavailable PDF source.

The operation boundary now decodes Base64 once, determines the input kinds actually expressible by that request, and filters sources by input compatibility before probing their matcher, checking availability or deciding the legacy PDF fallback. A strict text-only matcher is never invoked with a managed path. A text-only source remains usable for valid UTF-8 content; explicit adapter selection does not gain the implicit fallback. Actual Tasks selection and pinned source scheduling remain unchanged.

The unchanged parameterized review probe with `--expect-fixed` exited 1 on the preceding head and passed after the correction: both path and binary requests retain taskId plus failed-task behavior before/after adding the sibling, and valid textual PDF still imports. `test/pdf-import-routing.test.mjs`, `test/adapter-contracts.test.mjs` and `test/pdf-entries.test.mjs` passed 27/27, including compatible unavailable sources and explicit adapter errors. These use synthetic bytes, not a real PDF engine. Full build/test/package results and exact-head CI are recorded separately for each propagated head.

### Unified input-view selection correction

Review comment 6378709153 reproduced two public-entry failures at e8ac1c8: a no-format binary content-sniffing source could import through direct Tasks but not Base64 upload, and a lower-score text-only source displaced a higher-score byte source. The old entry prefiltered without content and chose the input representation before Parse could score it.

Input preparation and scoring now belong to Parse. Raw uploads retain owned bytes and a strict UTF-8 view. Compatible views compete together, one winning view per descriptor; different best descriptors tie with CONFLICT and no writes. Importer owns the existing missing-PDF wire compatibility rule. Tasks carries the chosen descriptor, version, mode and prepared input to execution without rematching. Registry/version drift fails closed. Built-in text adapters own UTF-8 validation; unrelated byte sources remain usable.

The new import-selection suite exposed six failures on the old head and now passes fourteen cases, including reverse multi-view scores, same-descriptor ties, caller-buffer/source-metadata ownership, unavailable isolation and queued selection freeze. Prior PDF entry tests now use real Parse/Tasks/Records with synthetic byte/path adapters instead of stubbing Tasks to inspect entry conversion. A focused combined run passed 42/42. The unchanged eleven-scenario review probe with --expect-fixed passes; observe-old exit 0 is not acceptance evidence. These are synthetic inputs, not real PDF or user-library migration acceptance. Full head-specific build/test/package/CI proof is recorded separately.
