# P03 adapter contract and import coordinator evidence

This branch is a staged P03 implementation on P02. It is verified on a branch and awaits integration; it does not mark P04, P05 or any PDF subpackage complete.

- `format` identifies a document or output type; `adapterId` identifies an implementation. Source descriptors declare supported formats, input kinds, version, binding schema and queue behavior. Tied matches fail rather than selecting registration order. A source must return a binding owned by its selected implementation.
- Importer owns parse-to-persist coordination. Records owns transactions, source IR, revisions and snapshots without mandatory Parse or Outputs injection. Translation-only compositions can omit Importer; import calls then return `COMPONENT_MISSING`. Read operations on existing records remain available if a source plugin is absent; human revision, model checkpoint and old-revision acceptance require the compatible private validator.
- Source IR resource identity stores `id`, `mediaType`, `contentDigest` and `version` without its location. The source binding retains private address and applicability data. Snapshots freeze the resource-version map and reject replay after a same-id content change.
- Output descriptors declare formats, binding/mode support and optional readable views. MD and JSON consume a normalized view; source-specific Markdown fidelity and PDF placeholder projection stay with their source adapters. Binary outputs do not require text projection. Renderers still receive frozen data, not a service object.
- Import tasks pin the selected source id/version. Export tasks pin selected output id/version at admission, recheck them on execution/resume, and record the actual id/version on artifacts. Missing or incompatible replacements fail explicitly. The direct Exporter compensates a newly created unreferenced snapshot if an adapter disappears before the frozen-stage check.
- The 0.1.0 PDF import wire response remains queued even if its optional component is absent; the resulting task reports the missing format. Direct Tasks imports still wait by default. Legacy TXT/MD/PDF paths are covered by regression tests.

Validation in this branch on Node.js 26.12.1: `test/adapter-contracts.test.mjs` covers same-format implementations, binary bytes, queue replacement/cancel, resource freeze, projection isolation, source validator version and direct-export compensation race. `test/pdf.test.mjs` and `test/tasks.test.mjs` passed 18/18 after the compatibility repair; `test/pdf-entries.test.mjs`, `test/mcp.test.mjs` and `test/tasks-lifecycle.test.mjs` passed 24/24 in the loopback-enabled environment. Full suite passed 291/291 (`node --test --test-concurrency=4 test/*.test.mjs`); `npm run build` passed with the existing pinned DSH `639ed015397290b3745d163aafe02ffee4aa3f84`; `npm run smoke:package` passed with a 70-file tarball, isolated parsing/reinstall/backup/settings/frozen exports/MCP/static UI. Loopback-enabled execution was required for the HTTP/MCP suite and package smoke. This evidence uses mock PDF fixtures and does not claim real PDF engine or three-platform installation acceptance.
