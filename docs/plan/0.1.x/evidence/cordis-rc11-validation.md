# Cordis RC11 candidate: independent runtime validation

This record compares the fixed production DSH source with the isolated Cordis RC11 candidate on the same ivoraige branch. It covers P01/P05 runtime behavior only. Source selection, bundle identity, and package smoke evidence belong to the build record for this candidate.

## Fixed inputs

- ivoraige candidate starts at `9c22bd38df1153624eb232db47d1cc67422e2b87` (PR #49, unmerged at the start of this validation); target `main` was `8dc548d9b08d8d6374c66920efca24135d9ce86d`.
- Production DSH pin is `639ed015397290b3745d163aafe02ffee4aa3f84`, whose vendor manifest identifies Cordis Core `4.0.0-rc.7` and Loader `1.0.0-rc.5`.
- Candidate Cordis Core tag `v4.0.0-rc.11` points to `0b96d9fd517b998e44e2209560c9e5f0671ce933`. The tag predates #209 service isolation merge `bc9a3449c4a307b68e046c92f999d882b18e009e` and #133 pending/failed dispose merge `5dac6953d2d993d345d1de9fb0a5926f6d78a7e7`. Passing probes below establishes observed candidate behavior, not inclusion of those later changes.
- Execution environment: Windows, Node `v26.12.1`. Tests use temporary directories and in-process or local loopback doubles; no user library, credentials, paid model, or external provider is accessed.

## Probe inventory

New `test/runtime-probes/cordis-rc11.test.mjs` directly exercises the bundled Cordis runtime. Its eleven checks cover the exact [#209 isolation derivation](https://github.com/cordiverse/cordis/commit/b2cafcc) and [#133 pending/failed state convergence](https://github.com/cordiverse/cordis/commit/7063517) scenarios, independent roots with identical service names, an asynchronous initialization/disposal race, reentrant effect disposal, repeated disposal during asynchronous cleanup, and withdrawal of an earlier logger exporter while a later one stays active. The remaining three guard DSH's existing `internal/plugin` behavior: an observer can add an injection before activation, reentrant disposal prevents callback execution, and a throwing disposal observer cannot starve other observers or cleanup. The dedicated probe directory keeps the production `npm test` baseline fixed; the candidate validation command explicitly runs these tests and does not skip their failures.

Existing consumer-path tests cover the behavior that matters to ivoraige: `test/foundation-runtime.test.mjs` verifies records consumers finish before storage closes, partial startup failure closes tasks and permits reopening the store, quota competition, and control during admission. `test/tasks-lifecycle.test.mjs` verifies abort and storage cleanup under direct root and plugin disposal. `test/model-settings.test.mjs`, `test/settings-pages.test.mjs`, and `test/settings-runtime.test.mjs` verify AppBoot profile restart, volatile model selection, mounted page changes, second settings-write failure, and reconciliation during disposal. `test/components.test.mjs` verifies installation state after restart. These use actual application consumers or local substitutes; they do not exercise paid provider calls.

The candidate uses Cordis Core RC11 plus a limited #209/#133 semantic overlay, RC8 Loader plus a limited DSH identity adaptation, and the fixed DSH Include/Group/Cosmokit/Schemastery sources. The precise source paths and hashes are in the candidate build evidence. The seven consumer failures arise despite successful profile boot and local test doubles; they are behavior regressions in the DSH volatile configuration boundary. The two lifecycle failures show the limited overlay does not retain every DSH Core hardening property. This tuple fails the P01/P05 gate. Repairing the remaining config semantics would require broader ongoing Core/Loader compatibility work and a fresh validation run; these failures must not be waived or attributed to model network access.

An earlier sandboxed consumer run hit `EACCES` on `127.0.0.1`; the final targeted run used permission for local loopback and that environment failure did not recur. The final bundle was verified by SHA-256 before execution; it was later replaced by the default pinned build, so reruns must explicitly select `IVORAIGE_RUNTIME=cordis-rc11` and rebuild first. Full suite, package smoke, and distribution results are recorded separately by the candidate build owner.
