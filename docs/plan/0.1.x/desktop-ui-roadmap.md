# 桌面外壳与 UI 渐进重置路线（讨论稿）

关联 [#105](https://github.com/KongouAirlines/ivoraige/issues/105)、[#29](https://github.com/KongouAirlines/ivoraige/issues/29)、[#16](https://github.com/KongouAirlines/ivoraige/issues/16)、[#35](https://github.com/KongouAirlines/ivoraige/issues/35)、[#71](https://github.com/KongouAirlines/ivoraige/issues/71)。本页提出执行顺序与跨包边界，不是框架决议、实现记录或发布日期；候选版本仍由 [releases](releases.md) 维护，状态只在 [work-packages](work-packages.md) 维护。

## 目标与替代关系

借完整桌面与 UI 完善作为排布工作的线索，同步重置旧 WebUI、逐页拆出可复用模块，并补齐普通翻译、设置、资源和项目等页面。替代“先只做托盘、完整原生 UI 整体后置”的排期，不采用一次性全面重写，也不让浏览器页面等待桌面壳全部完成。

第一阶段的 UI 验收要求之一是支持**无可视化前端、WebUI、完整桌面 UI、托盘菜单的按需组合**；这不是整条路线的终点，其后继续补齐新功能和新页面。无可视化前端不等于无后端，也不限定只有 CLI：内核、常驻 host、CLI/MCP 等非图形入口可依需要运行。完整桌面共享业务能力，不复制数据库 owner、任务系统、配置或修订真相。

## 现状与需要拆开的边界

源码核对基线：main `686dd3249d4d773eed38b1ca2888ca19bb565ef3`（2026-11-17）；本轮仅文档检查，没有原生或浏览器运行验收。

- `src/app.mjs` 已把内核操作与可选入口分开；`src/http.mjs` 承接 HTTP 操作映射。不能把旧 WebUI 称为业务内核本身。
- `web/app.jsx` 的 hash/history、页面切换和设置弹层属于 UI 路由，应该留在前端；但请求、事件失效、工作台选择与保存/接受流程仍与组件混合，需要拆分。
- `web/host-session.mjs` 有浏览器同源会话假设；`web/settings-runtime.mjs` 有生命周期注册，但实际组件仍静态绑定。已有 Cordis 接点不等于页面、安装包已全部可选。
- `package.json` 仍把 `dist/web` 与主体共同分发；无窗口运行不等于未安装 GUI。必须分别证明未安装、未加载、未运行三个状态。

目标依赖方向：

| 层次 | 职责与边界 |
| --- | --- |
| 内核/host 与协议入口 | 操作、任务、持久化、权限、修订冲突、事件及同一数据域的唯一 owner；不得反向依赖 UI 或原生壳 |
| 共用 UI client/controller | typed/可校验的操作请求、错误与取消、事件/快照、选中状态、编辑提交与冲突呈现；不拥有业务持久化或格式引擎 |
| 业务页面与注册 | 内容、任务、设置等可选视图；声明能力、路由、导航和 disposer；没有能力时明确缺件，不能显示假功能 |
| 共享应用壳 / UI Runtime（待研究） | 低于浏览器和桌面外壳的统一贡献接口、页面注册和生命周期；插件面向同一层交付视图/状态，具体加载与分发机制需验证 |
| 浏览器外壳 | 页面路由、历史/深链、主题、浏览器会话及上传下载适配 |
| 可选原生桌面外壳 | 窗口/菜单、启动/attach、原生文件交接与退出；托盘与完整窗口作为分别可选贡献，共享必要运行时 |

这是一组责任边界，不预先要求拆成固定数量的 npm 包。先由真实页面验证最小接口，再确定包边界。Cordis 负责依赖与生命周期，不自动完成依赖裁剪、权限隔离或任意原生模块热卸载；原生组件允许按明确的重启激活流程交付。

## 递进顺序与阶段验收

UI 完善只提供排布工作的线索，不是优先级高于其他功能的主线。后台能力、插件、格式与软件协作和 UI 同等重要，依据真实依赖、实际价值与可验证交付并行安排；不强制后台功能等待 UI，也不强制 UI 等待整个后台完成。沿现有 D/U/W 编号拆交付，不建立第二套状态账本。

### 第一阶段：迁移、重绘、修复与解耦同步

| 切片 | 内容 | 验收边界 |
| --- | --- | --- |
| 共享接缝与现有 UI 迁移 | D03 提取 client/session、事件失效、controller、页面注册；研究统一 UI 壳接口。以现有任务页验证，再逐页重绘首页、文档、工作台、模型/PDF 设置 | 保留实际已有能力、旧深链、前进后退、重连与错误语义；修正影响迁移/当前使用的已知问题，不把它们推到大重写之后 |

### 后续阶段：沿同一架构持续补齐新页面与功能

- U01 独立普通翻译优先切片；U02 新导航、设置分类、模型/连接管理及插件管理。插件管理才依赖 P05/PluginDelivery，普通页和基础设置不等待整个插件链。
- U03 术语、存储、预检；W02/W03 项目、可保存工作流和内容工作台逐项接入同一 UI 壳。对应后端交付后启用真实功能，不以静态页面冒充能力。
- 后续格式、软件联动、精翻及协作继续按各自契约扩展。每一功能同时考虑 Web/桌面视图和无可视化入口，不为新页面重新复制宿主逻辑。

阶段用于描述 UI 迁移和页面覆盖的顺序，不是全产品串行门禁：其他功能不比 UI 低优先级，可以依据价值与实际依赖并行交付，其发布不必等待第一阶段全部原生验收。D05 最终集成验收汇总 D01–D04 相关证据，候选探针和页面开发不等待所有工作包完成。普通翻译不等待项目/工作流；KT/Zotero、PDF 质量与格式工作保留自身依赖，不与完整桌面互相形成总门禁。[#35](https://github.com/KongouAirlines/ivoraige/issues/35) 单人编辑保存先于 [#36](https://github.com/KongouAirlines/ivoraige/issues/36) Git 协作；[#71](https://github.com/KongouAirlines/ivoraige/issues/71) 复用视图与状态、另适配 DSH 导航/权限，不阻塞独立桌面首批切片。

已知问题按[现有 follow-up 追踪规则](../follow-ups/README.md)及[工作包索引](work-packages.md)关联已有事项/issue，不另复制缺陷账本。影响当前切片正确性、安全或数据恢复的问题必须同步处理；不阻塞该切片的问题可有理由延期，但需记录原事项、影响、延期原因、重评条件与验收边界，不能笼统声称全部待修内容已经解决。

每页实施 PR 记录：旧入口 → 新页面/注册 → 使用的操作和事件 → controller/路由归属 → 已知问题与修复 → 保存恢复 → 浏览器与窗口验证 → 删除的旧代码。回退以页面为单位，不能回退权限、数据兼容或唯一 owner 护栏。

### 统一 UI 壳需要先证明什么

目标是 Web 与桌面窗口运行同一共享应用壳（UI Runtime），原生容器只提供平台桥。这不是统一一个必须安装的原生桌面运行时。“一次交付”指遵循统一 UI SDK、使用支持能力集的插件，通过同一前端模块向 WebUI/桌面提供页面、设置与命令；不使用宿主专属能力时无需分别编写两套界面。**这仍是待研究方案，不是已具备的插件运行机制。** 先以两个实际页面验证统一 SDK / 贡献清单（页面、设置、命令）、共享 renderer/client、依赖声明、版本兼容、注册/撤销与缺件表现。区分“一份代码双端使用”和“安装后免重建扩展”：后者还需独立设计可信来源、安全装载及版本边界，不能由前者直接推出；不把 Cordis 当作不可信前端的安全沙箱，再据此决定构建时打包或运行时装载。

同一页面内加载的 UI 插件与 owner 界面处于同一前端信任域，统一 SDK 是接口约束而非权限隔离。默认只装载适合该信任域的可信贡献；若支持不可信插件，需另行设计隔离运行及受控授权桥，隔离方案尚未选定，不能仅靠 Cordis 或隐藏 UI 来限制权限。

现有 `settings-runtime.mjs` 的 Cordis / DSH `settings.section` 是可利用的起点，但仍查询静态 `components[id]`，不能当作现成动态插件方案。tray-only 不依赖 UI Runtime、React 或完整窗口模块，只复用更薄的 actions/manifest/client 契约；具体契约仍需最小原型确定。

共享的是业务视图、状态和窄能力接口；浏览器 history、桌面窗口/菜单、文件对话框、授权与传输仍需平台适配。一次交付不代表任意原生能力自动跨平台，也不代表一个包无条件在所有平台运行。需证明：无可视化前端时不加载 UI Runtime、页面 renderer 或原生外壳，业务 host、CLI/MCP 按配置运行；共同支持的业务能力共享权威状态；平台专有能力显式声明支持条件并隐藏、降级或标为不可用，不强求两端功能完全相同；卸载释放贡献和监听；缺少平台能力可降级；协议版本不匹配可诊断；远端或自定义内容不能借共享注册点获得任意本机权限。

## 外壳候选与组合验收

保留 [#105](https://github.com/KongouAirlines/ivoraige/issues/105) 的 Electron、Tauri/WebView、轻量托盘加可选完整桌面三类比较。Electron 的一致 Chromium 与依赖体积、Tauri 的系统 WebView 差异与运行时部署、独立轻托盘的低成本与双实现维护都需实测。先验证现有浏览器功能、中文输入/剪贴板、文件交接、深链、WebView 会话、三平台托盘/无托盘降级，再决定框架；当前不宣布兼容或轻量结论。

| 安装/运行组合 | 必须证明 |
| --- | --- |
| 无可视化前端 | 可选择不安装 GUI 资源与原生壳；已安装时也可禁用而不加载 UI Runtime、页面 renderer 或原生外壳，无须卸载。CLI/MCP/host 按配置运行并可调用真实业务 |
| 仅 WebUI | 不安装原生壳，浏览器完成业务闭环 |
| 仅托盘 | 不安装完整桌面页面包，不启动隐藏 renderer；可控制入口、查看状态，按已装能力打开浏览器，否则给出明确缺件提示 |
| 仅完整桌面 | 不依赖托盘；可复用公共 UI 页面包及必要壳运行时，不要求另启对外 WebUI 服务 |
| WebUI + 托盘 / 桌面 + 托盘 / WebUI + 桌面（无托盘）/ 全部 | 同一数据域共用唯一 host、任务和修订；不同数据域可各有自己的 owner；并发编辑冲突可见；移除某入口不删除数据或停掉其他使用者 |

“仅完整桌面”不否认内部可采用受控 loopback 传输；不必暴露独立浏览器入口。优先保持既有可信同源路径，若采用自定义 scheme/IPC 则单独实现安全适配，不能靠放宽 Origin/CORS。报告每种组合的安装字节、进程树/空闲内存/CPU与冷启动；共享运行时成本与窗口增量成本分开，不把关闭窗口等同于零开销。

## 入口开关与视觉建议

`--no-mcp` 的目标语义是**本次启动初始关闭**，之后受信 owner 的明确开启命令可以覆盖。普通 attach、重连、打开窗口或读取状态不得隐式开启；无权限命令仍拒绝。覆盖是否保存到下次启动尚待决定，不能由这次 UI 重构默默选择。现有强制关闭实现与这一目标的差异须在独立实现 PR、兼容说明与回归中收口。

[#105 的 UI 建议](https://github.com/KongouAirlines/ivoraige/issues/105#issuecomment-6915604667) 作为改造方向而非定稿：考虑对旧 UI 的普遍不满及完整桌面迁移机会，采用文字优先、暖调纸感、克制编辑式排版，业务页面优先信息密度、对比度和编辑效率。

象牙桥插画只用于首页/欢迎页：低矮单拱、大块石材、略斜视角，桥与象牙白底同色、钢笔轮廓纹理；两侧大笔触水彩/水粉树花并有少量鲜艳花朵，不画山和房屋。水面 ASCII 设无/少量/大量三档，默认少量；深色用夜景版本。减少动态、隐藏暂停为建议验收项，插画不能侵入工作台或降低文字可读性。细节沿用 [原讨论](https://github.com/KongouAirlines/ivoraige/issues/105#issuecomment-6941188113)，不以插画完成阻塞功能切片。
