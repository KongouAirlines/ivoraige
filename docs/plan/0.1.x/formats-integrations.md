# 0.1.x 格式与软件协作路线

这是待实施规划，不是当前支持清单或日期承诺。格式能力依赖 P02/P03 的通用结构、来源绑定与二进制产物；软件协作依赖 P04/P05 的公共操作和兼容/安装契约，两条支线都不等待完整桌面壳或高级工作流图。执行状态只在[工作包表](work-packages.md)，通用组合见[工作流设计](../../requirements/0.1.x/workflows.md)。

## 来源与现状

[v1 F-07](../../requirements/v1.0/01_功能需求概览_v1.0.md)原有分期是 DOCX 原生往返按 P1、更多 EPUB/编辑工程按 P2；F-23/F-24/F-25 记录网页、OCR/截图以及 Zotero/笔记/知识库协作。优先级是历史需求的相对顺序，不是格式全范围必须随一个版本完成。[候选工具表](../../requirements/v1.0/02_候选工具与初步选型_v1.0.md)已有 Okapi、KISS Translator、Umi-OCR、Pot 和 Zotero 等来源，本页不将历史候选描述成已验证集成。

[v2 设计](../../requirements/v2.0/01_design_v2.0.md)曾列 EPUB/Zotero M7 和 Office → PDF，均不等于现状。[当前协议源码](../../../src/protocol.mjs)的导入格式仍仅 txt/md/pdf；`origin: zotero` 枚举不能证明 Zotero 插件已经实现。当前能力以[能力表](../0.1.0/capabilities.md)为准；本轮不补实现、不重写旧需求优先级或历史报告。

## 按能力分级，不笼统承诺“支持格式”

| 层级 | 可以声称的能力 | 独立验收 |
| --- | --- | --- |
| 提取/结构化读取 | 指定子范围中的文字、顺序、结构与资源可获得，并保留源定位 | 原件只读；明确未支持结构，不遗漏后仍报完整；不需要翻译或目标语言 |
| 可编辑翻译草稿 | 提取结果进入既有修订/接受/适用性与人工工作台，定位回来源 | 人工/模型/接受三路径校验；改译不破坏非文字内容；零模型的人工路径可用 |
| 原生回写/格式保留 | 将冻结的接受结果写入同类格式的新成品，并声明保留范围 | 原文件不覆盖；来源绑定、资源/关系、非翻译内容完整；目标应用可打开和人工抽查；不是仅改后缀或 Office → PDF |

每层由具体 adapterId/版本及测试样本证明；同一格式可以有多个读取或输出实现。预览、文本提取、可编辑成品和视觉保真分别报告。不同格式不共用“全文不损失”的泛化结论，不能因解析库支持格式就承诺原生往返。

## 格式支线

| 工作包 / 格式 | 起步范围与关键验证 | 暂不承诺 |
| --- | --- | --- |
| F01 DOCX | 先正文/标题/列表/普通表格，保留段落/单元格/文本范围定位、run 样式、超链接与字段边界；回写新 DOCX。跨 run 文字不重漏，打开无修复提示与视觉抽检分开验收 | 页眉脚注、文本框、批注、修订、域、公式和嵌入对象逐项标为支持/保留不译/不支持；不把全部 OOXML 结构算已支持 |
| F02 EPUB | 无 DRM 的可重排正文优先；按 OPF spine 读取 XHTML，保留 manifest/nav、章节与脚注锚点、图片/CSS 资源关系；EPUBCheck 合规和阅读器视觉抽查分别验收 | 不绕过 DRM；固定版式、SVG 主体、漫画、音频同步及脚本化交互后置；不承诺所有阅读器一致渲染 |
| F03 PPTX | 幻灯片/形状/文本框定位，保留 slide/master/layout/theme/notes 关系、页序及非文字对象；提取与原生回填分别验收；长译文溢出须提示/人工处理，不默认无限缩小字体 | 自动完美重排、SmartArt/图表/动画/嵌入对象全部往返；Office → PDF 只算可读预览，不替代 PPTX 原生回写 |
| F04 XLSX | 本轮 Office 范围新增候选，旧规划未明确。只译用户选区文本，保留公式/数值/日期/工作表名；同一 shared string 在不同单元格可有不同语境，不全局替换；保持文本类型，`=` 开头译文也不能变公式 | 公式翻译/计算引擎、宏执行、复杂外链刷新、图表/透视表无损；不得把公式或公式缓存当可译文字 |

DOCX 与 EPUB 优先建立窄范围端到端路径；PPTX、XLSX 分开评估和交付，不将“Office”当一个验收项。旧二进制 `.doc/.ppt/.xls`、ODF、加密文档、嵌入对象等另列待评估；需要转换时保存明确来源链及损失说明，不能把转换成 PDF 说成原生格式支持。

上述边界依据 [WordprocessingML 结构](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document)、[PresentationML 结构](https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document)、[shared strings](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-the-shared-string-table)与[公式](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-formulas)的一手资料设定，并非已有适配器的通过结论。`.docm/.pptm/.xlsm` 等宏格式另列，不暗含支持。

[EPUB 3.3](https://www.w3.org/TR/epub-33/)中的 `encryption.xml` 也可登记字体混淆，不能看到该文件就一律判为 DRM。按声明算法和资源类型分类，保留适用资源及许可；不支持或受 DRM 限制时明确报告，不绕过保护。[EPUBCheck](https://www.w3.org/publishing/epubcheck/)用于规范合规检查，不替代目标阅读器的视觉与导航验证。

可评估既有候选中的格式过滤/回填工具与适用的结构化库，先验证实际 API、版本、许可、产物闭包及损失边界再选定。复用成熟组件，不自造 OOXML/EPUB 引擎；当前规划未锁定新依赖，也没有把历史工具简介算作本项目接入证明。

## 软件协作支线

| 工作包 / 候选 | 首次可验收切片 | 边界与未决 |
| --- | --- | --- |
| I01 Zotero | 用户选择条目/附件 → 导入关联 → 公共任务 → 新产物显式附回原条目，拆成只读导入和写回两个验收切片。保存 library/item/attachment 身份及源版本，幂等避免重复附件，展示目标和内容确认 | 不假定首个附件就是正确输入；文献管理归 Zotero。桌面插件/本地 API/Web API 的具体组合与版本需探针选择；旧 v2 四模式/RAG/双语 PDF 不全作首轮门槛，不替换原附件 |
| I02 网页与截图入口 | 依历史 F-23/F-24，第二阶段先在 KISS Translator/Pot 中选择窄范围选文输入、返回结果；Umi-OCR 可只识别完成。复用 P04 公共操作，固定实际客户端版本 | OCR 与翻译分别授权/计费，入口插件不建第二翻译内核；不笼统声称全平台兼容，不承诺三个软件同时完成 |
| I03 笔记/知识库与电子书文件交换 | 先固定结构化内容/附件/元数据和关联引用契约；历史已有 Obsidian 可先 Markdown + 资源文件交换，calibre Ebook Translator 先文件级候选 | 不要求插件或双向同步才算首片；其余知识库软件由实际需求再选，不编造确定名单/日期；远程空间、自动覆盖/自动上传不作为默认 |

集成通过能力、operation、类型化资源和来源引用接入；工作流可调用这些能力，但简单导入/导出仍可直接使用。Zotero 导入和显式回写是不同能力，回写不是导出的隐式副作用。来源 URL/外部对象标识是定位线索，不构成访问授权；本地与远程凭据继续由 DSH 管理。

桥接前先固定通用协作契约：来源/文件交接、处理方案或目标输出、任务状态/取消、产物获取、幂等与权限错误；客户端只获受约束操作，不暴露宽权限核心端口。候选接口入口见 [Zotero 插件文档](https://www.zotero.org/support/dev/client_coding/plugin_development)、[KISS Translator](https://github.com/fishjar/kiss-translator)、[Pot](https://github.com/pot-app/pot-desktop)和 [Umi-OCR HTTP 文档](https://github.com/hiroi-sora/Umi-OCR/blob/main/docs/http/README.md)。这些链接是实施前版本/协议复核起点；本轮没有联调、依赖选定或工期估算。

## 共同验收与恢复

1. 安全与选择：明确文件/条目/远程目标和授权范围；保留既有 Host/Origin/认证边界，不能为本机软件方便而开放任意跨域。导入不执行宏、脚本、外链更新或自动下载未知附件；包内路径越界、解压膨胀、畸形关系、远程资源按受控资源边界检查。
2. 身份与重复：外部对象身份包含所属库/账户范围和对象标识，内容/修订版本另记。相同对象重复导入可关联已有文档，但新内容形成新来源版本；同名文件或相同哈希不能自动合并不同业务来源。保留 applicability 检查，不自动重复翻译。
3. 显式写回：源文件默认只读，原生输出写新成品；外部写入显示目标及影响并确认，使用幂等/收据记录。上传成功但响应丢失时先查询；不能确认则标未知并要求人工处理，不能盲目重试或把禁用插件当撤回外部写入。
4. 外部变化：重命名、移动、删除、权限变化、外部附件或链接更新，展示失联/过期并提供重新关联；不凭旧绝对路径或 URL 自动读取/覆盖另一对象。再次导入与替换绑定必须显式、留痕。
5. 生命周期：客户端关闭不隐式停止已由 host 接纳的任务；取消、网络断开、凭据失效、版本不兼容与插件卸载保留本地记录/产物，恢复核对原版本和外部目标。无此插件时历史记录仍可读，受其私有校验约束的写操作明确不可用。

各格式按同一套小型公开/合成样本分别验收提取、草稿、原生输出、错误/缺件和实际独立安装；人工检查长译文、复杂结构与目标软件打开效果，机器可打开不等于排版合格。格式与协作的实际包各自满足 P08 同类闭包/许可要求，真实外发/付费调用按既有授权执行。

0.1.0 只固定通用契约和 W01 最小组合证明，不以全部格式/客户端完成为基础门槛；后续按[候选分期](releases.md)将 DOCX/EPUB、Zotero 首片纳入优先支线，其他能力经窄范围验证再安排，不机械全塞入 0.1.1/0.1.2。这里以阶段、依赖和优先顺序承接日程需求，没有约定日历日期。新增支线不会改变 npm 暂不上架、PR #33 历史索引后置及旧报告保留的约束。
