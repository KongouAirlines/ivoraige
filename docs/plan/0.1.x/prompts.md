# 0.1.x 统一开发提示词

公共约束唯一来源为 [AGENTS](../../../AGENTS.md)；接口来源为 [0.1.x 契约](../../requirements/0.1.x/contracts.md)，兼容与回退见 [迁移分发](migration-distribution.md)。以下模板只写任务差异，不复制不变量、安全规则和 GitHub 规则。每次任务选一个主模板，按需组合检查项。

## 共用任务头

```text
在 KongouAirlines/ivoraige 执行 {工作包 ID / 原事项 ID}。
目标/可观察结果：{结果}。
基线：{提交/目标分支}；相关进行中工作：{分支/PR/负责人或未核实}。
先读 AGENTS.md、适用目录指引及 .agents/skills（若存在），
再读 docs/requirements/0.1.x/contracts.md 和本工作包链接。
输入与证据：{固定提交/文档/fixture}。
允许改动：{文件/服务/协议}；不做：{范围}。
验收：{验证矩阵编号、定向命令、环境及所需真实证据}。
回退：{功能开关/兼容层/备份及恢复}。
交付：最终差异、实际检查、未测项、原事项状态更新、下一步。
Git 动作范围：{本地提交 / 已授权的推送或 PR 等}；不推断额外发布授权。
```

涉及 W/F/I 包时，在任务头追加定义/输入/能力版本、目标输出与副作用范围，并引用[工作流契约](../../requirements/0.1.x/workflows.md)或[格式/协作路线](formats-integrations.md)的对应验收；不把规则再复制进八个模板。历史记录迁移、模板分享和外部写回分别给出允许范围。

## 八类主模板

| 模板 | 在共用任务头后添加的指令 | 特有输出 |
| --- | --- | --- |
| T01 基线审计 | 核对仓库 ID、远端/本地 SHA、工作区及进行中分支。只审与工作包相关的代码/历史发现，按现存、部分修复、历史已修、建议、未验证区分，先查重；别把旧条数当当前缺陷数。 | 固定源码定位、复现/未运行界限、旧 ID 到工作包映射、阻塞缺陷 |
| T02 契约规划 | 对照当前实现逐项写目标服务、必需/可选依赖、注册/释放、缺件/错误、兼容版本。新 API 标为草案；用最小 fixture 计划证明，不用大框架填空。 | 当前/目标差异、契约表、决策选项、迁移/验收及可独立 PR |
| T03 功能开发 | 仅实现指定工作包；先确认契约已启用部分，保留兼容路径。把代码、定向测试、契约及受影响用户文档同 PR 更新；已完成条件以实际证据判断。 | 可审阅实现、影响与回退、实际命令结果、未完成范围 |
| T04 插件接入 | 声明输入/输出/adapterId/format、依赖与用途、版本、资源、取消/恢复及 disposer。冻结主体后只增插件/配置；若需主体特判，先报告契约失败并收窄修订。 | 独立包/清单、缺席/安装/失败矩阵、主体 diff 证明、真实插件与 fixture 的区别 |
| T05 故障排查 | 先复现并记录实例/任务/插件/快照版本；区分领域校验、协议、引擎质量、安装、进程生命周期。验证最小原因，保留原错误与恢复证据，不扩大重构。 | 根因证据、最小修复、回归与恢复结果、不能确定部分 |
| T06 架构检查 | 按契约追踪实际依赖/数据/资源所有者，检查格式/供应商分支、反向依赖、ctx 泄漏、任务/事件寿命和卸载行为。证明影响，不因命名或文件大小判定架构问题。 | 违规位置和触发条件、现有正确机制、最小调整、原事项关联 |
| T07 PR 审阅回复 | 依 AGENTS 的 GitHub 规则逐条核实意见与当前 diff；修复/不同意/延期分别给技术依据及验证。不把回复、resolved、approval、merge 混为一件事。发表范围按共用任务头。 | 可发布回复草稿或已授权的实际回复、对应提交/检查、仍未解决问题 |
| T08 发行安装验收 | 从实际待分发包核对源码/版本/摘要/依赖闭包/许可与文档，干净环境测主体及插件分装、首次启动、升级/回退和数据保留。逐平台列实测/未测，不复用历史附件结论。 | 归档来源表、安装/恢复证据、发行阻塞及平台边界；不自动发布 |

模板不创建新状态源。任务进展写回 [工作包表](work-packages.md)，旧 follow-up 按原记录规则更新；历史报告只引用。T07 涉及 GitHub 协作时使用可用的 github-collaboration 技能；PR 标题/正文使用 pr-writer，且都服从当前用户的发表范围。
