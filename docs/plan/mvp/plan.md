# 项目启动与 MVP 实施计划

日期：2026-09-30｜状态：M0～M3 工程阶段已完成。M2 的 6 dev＋2 原创真实建库／翻译／审校／修订／复用验收与 M3 的 R03 实际 PDF 第 1／2／4 页三出口闭环通过；自动科学质量未全过，用户专业签认待继续。详见 [M2 真实验收](m2/real-acceptance.md)、[M3 完成记录](m3/README.md)与[M1 结论](m1/completion.md)。

依据：[需求基线 v1.0](../../requirements/v1.0/01_功能需求概览_v1.0.md)。以下是实施拆分建议，不重新调整需求优先级。MVP 指首个可用闭环；M0～M4 为本计划里程碑，与需求版本号无关。

## 1. 建议的启动顺序

先用半天左右明确首个用户场景、样本和成功条件，再安排约 1～2 个工作日的 Cordis 定向调研与关键适配实验。时间仅用于限制调研范围，不是交付承诺。遇到明确阻碍时记录证据与替代方案，再调整计划。

顺序为：**需求与样本 → MVP 范围草案 → Cordis＋DSH／PDF 两项验证 → 架构选择 → 文本闭环 → 同源 PDF 闭环 → 日常使用完善。**

Cordis 值得优先调查；它在既有候选池中也是优先对象。但是否采用它，与是否基于完整 DeepSeek Harness 开发，应分别决定。调研应产出可复现的小实验、限制清单和决策，而不仅是一份框架介绍。

## 2. 首个可交付场景

用户导入一篇受支持的英文科研论文 PDF，指定模型与共享／项目术语库，系统解析并生成可追溯的文本块，执行术语辅助翻译，将已接受译文保存，再生成译文 PDF、Markdown 和 JSON。重新导出其他格式时，不重新调用正文翻译模型。

独立文本入口共用同一翻译核心，支持科研英译中和学术中译英。论文 PDF 首批先验证英文到中文。其他语言、复杂扫描件及特殊版式保持扩展能力，逐步扩大支持范围。

“同源输出”先保证同一文档经一次规范化后的多个出口复用。不同解析器、不同版本或不同格式重新导入后的自动对齐，另属 F-39 等后续能力，不能仅凭文本相似度宣布已经支持。

## 3. P0 到 MVP 的具体映射

| 需求 | MVP 中的最小范围 | 验收证据 |
|---|---|---|
| F-01 模块化 | 解析、模型、术语、译文存储和输出有明确边界，至少演示模型适配器替换 | 切换实现不改翻译业务逻辑；生命周期实验通过 |
| F-03 用户设置 | 显式选择模型端点、联网开关、术语库及启用步骤 | 实际请求遵守配置；关闭联网时不请求外部模型或服务 |
| F-05 独立翻译 | 句段和小文档入口；科研英汉两个方向 | 脱离 PDF 解析也能完成翻译 |
| F-06 PDF 重建 | 一条受支持的论文 PDF 路线 | 输出可打开；抽检阅读顺序、公式、图表与文字溢出 |
| F-07 结构化输出 | 同一文档生成 Markdown／JSON，并与 PDF 共用译文 | 三种输出可追溯到同一译文记录／修订版本 |
| F-11 模型分工 | 建库模型与正文翻译模型可分别配置；审校步骤可关闭 | 请求日志显示各阶段采用指定模型 |
| F-13 译文复用 | 已接受译文持久化；重复运行／增加输出格式直接复用 | 无变更重跑及重导出时，正文翻译请求增量为零 |
| F-14 指定语料建库 | 从少量指定论文／文本提取候选术语，保留出处并允许确认 | 候选可追溯到来源，确认后能被翻译调用 |
| F-15 知识管理 | 术语原文、译名、别名、来源和状态；编辑、合并及导入导出 | 修改后可读回，来源和状态不丢失 |
| F-17 词库组合 | 共享库与项目库同时使用，确定冲突规则 | 同名术语冲突可解释；项目约定可覆盖共享建议 |
| F-27 的 P0 部分 | 接一个现有本地兼容端点；复用模型适配接口 | 本地请求通过且不会无提示切到远程；部署管理留 P1 |
| F-30 的 P0 部分 | 任务状态、进度、取消、失败位置 | 取消后不再派发新翻译请求，在途结果按明确规则处理 |

MVP 可以借助简单配置、CLI 或最小本地页面完成操作。暂不以完整精翻工作台为交付前提；用户仍须能够查看、确认和修正术语。

F-40 外部词典维持 P1：设计阶段定义可替换的查询边界，在 MVP 后首批完善中接入一个用户常用来源；不要求一次接完本地和在线所有词典。F-29 MCP 与 F-28 对外兼容入口同样维持 P1。对内调用模型的兼容 API 与对外提供翻译服务是两件事。

## 4. 先验证的两个问题

### A. Cordis 与 DSH 现成模块能否降低实际接入成本

沿 Cordis 服务机制与 DeepSeek Harness（DSH）的真实模型调用路径一起调研，优先尝试复用模型提供商、兼容端点、配置、流式请求、取消和用量处理。用真实框架／模块连接本地模拟模型服务，验证必要的依赖、替换和释放行为；区分可独立复用的模块与依赖完整应用的能力。无需真实模型密钥，也不预先限定采用独立 Cordis 或完整 DSH。

待验证的业务边界可先称为 `Parser`、`ModelProvider`、`TermProvider`、`TranslationStore`、`Exporter`。这些是项目讨论用名称，不是 Cordis 已有 API，也不是定稿接口。

插件卸载／事件清理、任务取消、进程重启后的恢复是不同问题。不要把框架生命周期管理直接当作持久任务系统。

### B. pdf2zh-next 能否消费已有译文并重建 PDF

先克隆 pdf2zh-next 及必要核心依赖，检查真实翻译接口与 PDF 重建路径。MinerU 负责解析，本身没有翻译步骤；注入目标是 pdf2zh-next／其重建核心。关键问题：能否注入已有译文、怎样对应实际文本块、是否重新分段或改写、是否还有额外模型调用、长译文怎样排版。先验证工具自身的块映射，不提前强制不同解析器采用相同分块。

用固定译文和一个会记录调用的模拟模型验证。先导出 PDF，再导出 Markdown／JSON；导出期间正文翻译调用必须为零。保留输入、块映射、输出和调用日志。

若 PDF 重建必须重新翻译，则该路线尚不满足 F-13。应调查可替换翻译回调或适配层；仍不可行时换候选，或明确记录需要调整 MVP 范围的原因。仅有 Markdown／JSON 的原型是中间成果，不能称为完成了原规划的 PDF MVP。

## 5. 里程碑和退出条件

| 阶段 | 工作与产物 | 进入下一阶段的条件 |
|---|---|---|
| M0 范围与样本 | 采用短篇双语论文、磁学章节选段、现代计算物理 PDF 三类样本；准备对齐、术语及原创控制例子，详见 [M0 执行清单](m0/plan.md) | 当前清单m0-corpus-002已落实反馈，001出版摘录保留；24个真实单位、12 dev／12 heldout、16义项及代表PDF页可用；具体新增说明与变体为agent修订 |
| M1 技术验证 | 已完成：DSH 真实模型模块 10 项检查、BabelDOC 两页译文回放及重跑、运行时决策 | 接入机制通过；真实科研页、解析遗漏和跨解析器映射在 M3 验收 |
| M2 文本闭环 | 独立翻译、基础建库、词库组合、模型分工、译文存储、Markdown／JSON、进度取消 | 基本翻译可用；译文复用可测；本地模型入口可验证 |
| M3 PDF 闭环 | 固定来源位置映射、接受译文重建 PDF、三个出口联调 | R03 第 1／2／4 页代理工程与目视验收通过；离线重导出正文模型请求 0；未作用户专业签认或跨 PDF 通用承诺 |
| M4 个人使用完善 | 外部词典、解析校正、双语编辑、方案保存；再按需求推进暂停恢复、MCP 等 | 按真实使用反馈决定范围，不一次搬入全部 P1 |

M3 是本建议中首个满足核心目标的 MVP 交付点。M2 的复用要求需要保存已接受译文，但不代表完成 F-31 的备份迁移或 F-39 的外部翻译记忆体系。M3 暂不承诺扫描整书、所有复杂表格及跨文件完全自动对齐。

## 6. 数据与验收先约定什么

建议先用一个小样定义逻辑数据：文档、来源位置／文本块、翻译目标、术语条目、译文修订、任务状态和输出引用。先验证它们之间的对应关系，再确定数据库和协议字段。

复用判断需要包含原文、语言方向、翻译目标、相关上下文及术语／风格约束。不能仅按原文字符串缓存。模型与提示词版本要记录为来源信息；换模型是否重译由明确操作决定，不能无条件覆盖已接受或人工修改的译文。约束变化后的精细增量更新留给后续实现。

验收清单（相关条目已有 M2／M3 小样证据，其他范围仍按原计划核对）：

- 相同输入、相同目标和已接受译文下，第二次运行的正文模型调用增量为零。
- 增加 PDF／Markdown／JSON 出口不触发正文翻译；各出口引用的译文版本一致。
- 已确认术语在测试句段中正确使用；歧义词允许有记录的例外，不只检查机械字符串命中。
- 术语或翻译目标变化后，旧译文的适用性需重新判断，不静默混用。
- 模型超时、解析失败和取消均有可定位状态；人工已接受的结果不会被静默覆盖。
- 输出公式、图片与来源关联可追溯；抽检发现的漏段、顺序错误或溢出均记录。
- 耗时、调用数与可获取的 token 用量有记录；缺失用量标为未知，不填成零。

首轮完整性、科学含义与复用门槛见 [M0 验收标准](m0/plan.md)。速度与成本在首次真实运行后建立基线；当前未承诺固定准确率、吞吐或工期。

## 7. 后续工作边界

M2 真实流程证据见[验收记录](m2/real-acceptance.md)，M3 固定代表页、同源输出及失败／取消证据见[完成记录](m3/README.md)。后续按用户最新方向与[M0–M3 总结](retrospective.md)确定 [M4 范围](m4/README.md)：优先收敛通用接口和适配边界、算法检查与自动选定版本，不把用户再次复核或模型全文审校作为默认前置。无需为 M3 无差别重跑语料。[术语范围需求](../../requirements/amendments/0001-term-applicability.md)保留，待建库和库结构明确后实施，不追认其已由 M3 完成。

M3 的页 4 矢量字段、图内文字和页 1 脚注使用 R03 来源位置的具体修复，应保留为实验案例，不能替代通用方案。新原件或解析配置需要适用的来源绑定；运行时优先算法检查，开发阶段按需抽样比较上游基线，不要求每份新文件逐页人工验收。已证实属于上游的输入输出缺陷可记录后暂不修；本项目新增的丢失、错配和结构损坏应修复。M2 自动质量局限及几何／H 约定疑点作为历史证据保留，不由此要求所有后续任务人工签认。
