# M3.1：模块边界整理计划

日期：2026-09-30。依据用户确认的[M0–M3 总结](../retrospective.md)。

状态：已完成，实际验证范围与限制见[完成记录](completion.md)。

## 目标与范围

将 M3 中已验证的能力整理为可替换的最小模块。核心记录不识别 BabelDOC 占位符或页面坐标，解析与 PDF 输出分开；R03 专用修复不再默认执行。保留已有接受修订、来源适用性、三出口与取消行为，不重新翻译已有材料。

本轮不接入完整 Docling／MinerU 运行时、不扩展术语库、不建设全格式中间表示或动态插件市场。自动版本选定是后续工作；当前 draft／accepted 行为保持。

## 实施边界

| 部分 | 本轮职责 |
|---|---|
| 核心记录 | 通用文档单位、稳定 ID、来源修订、接受版本；保存但不解释工具来源绑定 |
| 来源处理接口 | 由选定适配器验证结构、生成可读投影与所需翻译提示；缺必要适配器时报清晰错误 |
| 解析入口 | 把来源快照转换为通用单位；不要求该解析器具备 PDF 重建能力 |
| BabelDOC 适配 | 特定 snapshot、`<bN>`、位置与旧记录兼容；引擎 hook 保留在 Python 侧 |
| PDF 输出入口 | 消费一份冻结接受清单、调用选定后端、处理取消和诊断；文本出口复用现有呈现逻辑 |
| R03 实验修复 | 固定坐标／字段的恢复逻辑隔离且显式启用，仅保留为历史实验与回归材料 |

模块按职责拆分即可，不要求每个模块单独发布包。旧 M3 存储与接受清单需能通过适配读取或明确迁移，不静默重写接受修订。

## 验收

1. 核心记录及翻译流程不再解释 BabelDOC token／PDF 坐标，工具规则由适配器提供；纯文本流程可独立运行。
2. 另一种原创来源结构通过同一导入与记录接口，证明新增来源不必修改核心。该测试不冒充已经接入 Docling。
3. R03 补丁默认关闭、显式实验入口可复用既有清单。一个已有真实页通过模块化出口重建，三出口单位／修订一致，新增正文请求为零。
4. 一个不同布局的原创小样通过默认路线，检查没有依赖 R03 ID／页码；上游固有缺陷记录即可，不展开样本精修。
5. 覆盖适配器缺失、结构不适用及取消等受影响边界，运行现有回归；已通过且未受影响的样本不重复全量处理。

完成记录应明确验证范围、兼容方式和仍未模块化的部分。无需用户逐页复核才能结束这一工程阶段。
