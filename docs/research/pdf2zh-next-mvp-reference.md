# pdf2zh-next 固定源码参考（不阻塞 MVP）

只读范围：pdf2zh-next `f8dffcf4c3a33b254391d43514439b975ce8d966`；BabelDOC `38d3896dcde9b5a940c62cf5563cadea673a64d3`。以下仅说明固定源码的控制流和配置，**不是两套程序实际输出差距的实验结论**。

用途：按用户决定跳过 M3.2，先完成 M4 CLI。以下结论留作后续改进参考，本轮没有改占位符规则、翻译器或排版参数。

1. **翻译器构造。** pdf2zh-next 根据 `translate_engine_settings` 的模型类型查元数据，动态导入对应实现，先用 `Hello` 做一次忽略缓存的健康检查，再交给 BabelDOC。[translator/utils.py:31–74](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/f8dffcf4c3a33b254391d43514439b975ce8d966/pdf2zh_next/translator/utils.py#L31-L74) [high_level.py:531–534](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/f8dffcf4c3a33b254391d43514439b975ce8d966/pdf2zh_next/high_level.py#L531-L534)
2. **BabelDOC 配置。** `create_babeldoc_config` 将翻译器、语言、页码、QPS、术语表、字体族与 PDF 选项传给 `BabelDOCConfig`，`doc_layout_model=None`，表格文字选项开启时另建表格模型。[high_level.py:575–630](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/f8dffcf4c3a33b254391d43514439b975ce8d966/pdf2zh_next/high_level.py#L575-L630)
3. **正文译文流。** BabelDOC 段落路径调用翻译器的 `llm_translate` 或 `translate`，接着直接进行段落后处理；pdf2zh-next 的翻译器在缓存检查、限流后返回服务结果，没有人工 `accept` 环节。[il_translator.py:1234–1267](https://github.com/funstory-ai/BabelDOC/blob/38d3896dcde9b5a940c62cf5563cadea673a64d3/babeldoc/format/pdf/document_il/midend/il_translator.py#L1234-L1267) [base_translator.py:72–112](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/f8dffcf4c3a33b254391d43514439b975ce8d966/pdf2zh_next/translator/base_translator.py#L72-L112)。本项目则要求 manifest 记录为 `accepted` 后才回放。[adapter.py:112–149](../../experiments/pdf-injection/adapter.py#L112-L149)
4. **占位符与异常。** BabelDOC 的 `all_match` 逐个查找占位符模式，未见顺序或次数等值约束；解析使用译文中的匹配顺序，故源码路径容许重排。未完全匹配时记日志，仍继续解析；多余的同形幻觉 token 会清除。普通段落异常被记录并跳过，批量 LLM 的长度／原文相同等检查失败则回退普通翻译路径。提示词虽要求不重排，但不是该解析函数的硬校验。[il_translator.py:810–858](https://github.com/funstory-ai/BabelDOC/blob/38d3896dcde9b5a940c62cf5563cadea673a64d3/babeldoc/format/pdf/document_il/midend/il_translator.py#L810-L858) [il_translator.py:860–952](https://github.com/funstory-ai/BabelDOC/blob/38d3896dcde9b5a940c62cf5563cadea673a64d3/babeldoc/format/pdf/document_il/midend/il_translator.py#L860-L952) [il_translator.py:1263–1278](https://github.com/funstory-ai/BabelDOC/blob/38d3896dcde9b5a940c62cf5563cadea673a64d3/babeldoc/format/pdf/document_il/midend/il_translator.py#L1263-L1278) [il_translator_llm_only.py:768–848](https://github.com/funstory-ai/BabelDOC/blob/38d3896dcde9b5a940c62cf5563cadea673a64d3/babeldoc/format/pdf/document_il/midend/il_translator_llm_only.py#L768-L848)。本项目的 accepted manifest 允许有理由的占位符重排，且要求 token 多重集和 `engineProjection` 顺序一致。[adapter.py:112–121](../../experiments/pdf-injection/adapter.py#L112-L121)
5. **布局、字体、富文本默认值。** pdf2zh-next 配置默认 `disable_rich_text_translate=False`、`primary_font_family=None`（自动选择）、`translate_table_text=True`、`skip_scanned_detection=False`；传入 BabelDOC 时布局模型为 `None`、字体参数为 `None`。[config/model.py:126–128](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/f8dffcf4c3a33b254391d43514439b975ce8d966/pdf2zh_next/config/model.py#L126-L128) [config/model.py:160–188](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/f8dffcf4c3a33b254391d43514439b975ce8d966/pdf2zh_next/config/model.py#L160-L188) [high_level.py:575–600](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/f8dffcf4c3a33b254391d43514439b975ce8d966/pdf2zh_next/high_level.py#L575-L600)。BabelDOC 的 `FontMapper` 按目标语言取字体家族。[fontmap.py:35–66](https://github.com/funstory-ai/BabelDOC/blob/38d3896dcde9b5a940c62cf5563cadea673a64d3/babeldoc/format/pdf/document_il/utils/fontmap.py#L35-L66)
6. **与现有 adapter 的配置差异。** 本项目显式加载固定 `doclayout_yolo_docstructbench_imgsz1024.onnx`，关闭富文本翻译、自动术语抽取和 OCR 自动处理，跳过扫描检测，单 worker，并用已接受的回放译文；pdf2zh-next 的上述默认值及自动选择路径不同。这里只标出配置差异，不推断字体、布局质量孰优。[adapter.py:179–239](../../experiments/pdf-injection/adapter.py#L179-L239) [high_level.py:582–619](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/f8dffcf4c3a33b254391d43514439b975ce8d966/pdf2zh_next/high_level.py#L582-L619)

## 后续如何使用这些结论

- 本项目默认的草稿入口仍按原 token 顺序严格检查；上述 accepted 回放支持的是**事先记录原因的顺序修正**，并非任意模型重排已自动获准。见 [BabelDOC 来源适配](../../src/adapters/babeldoc-source.mjs)。后续研究 token 身份与结构关联时参考上游匹配机制，不直接照搬其异常放行方式。
- 先对齐富文本、表格、字体与段落处理配置，再做少量同输入的排版比较。上游传 `None` 只表示由 BabelDOC 自动装配，不能据此断言最终布局模型或字体一定不同。
- 上游直接消费译文可供日常流程参考，但本项目的可追溯修订与零模型重导出仍需保留。未来版本选择策略可独立实现，不必为了取消人工逐条操作而移除复用记录。
