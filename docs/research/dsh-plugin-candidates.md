# DSH 插件复用候选：v1.1 选型补充

日期：2026-09-29。核验对象是本地 `experiments/vendor/deepseek-harness/`，固定提交 [`639ed015397290b3745d163aafe02ffee4aa3f84`](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84)，所列 DSH 包清单版本为 `0.2.0-rc.2`。本轮阅读包清单、入口源码与对应 README；没有安装插件、运行新增实验或调用模型。既有模型实验结果沿用 [Cordis 与 DSH 调研](../mvp/m1/cordis-harness.md)。

本表精选 14 个组件或组合，服务当前翻译、术语和译文复用，以及后续任务、界面和外部接口。**允许一并复用 DSH 的 agent、session、workspace 和客户端组件**；依赖这些组件不会自动淘汰候选，是否值得引入取决于它们是否同时解决本项目实际需要。P0/P1/P2 对应 v1.0 功能优先级，不代表这些包已经纳入实施承诺。

## 注入、传递依赖与固定源码证据

下面区分三种证据：`inject` 是插件显式服务门槛；包的 dependencies/peerDependencies 是发布与构建关系，可能包含类型契约或可选能力；`ctx.inject`／`ctx.get` 是按功能接入。**peer 列表不能直接当作全部必须常驻的服务列表，未声明 inject 也不等于零依赖。** 所列为关键依赖路径，完整发布闭包仍以固定源码 package.json 与实际组装为准；`/invariant` 是独立伴随入口，需要 invariants 时才装，不作为每个插件的隐含硬门槛。

1. **模型基础**：真实包为 `@deepseek-ai/cordis`、`@deepseek-ai/dsh-llm`、`@deepseek-ai/dsh-llm-pi-ai`。pi-ai 入口 `inject=['llm']`；credentials、authorization、settings 等按能力解析或可选注入。llm 拉入 Typert protocol、brand、crypto、timeout、values、Schemastery/zod；pi-ai 拉入 `@earendil-works/pi-ai` 和其各厂商 SDK。统一使用 DSH vendor 的 Cordis 身份，不能直接混用独立 Cordis。见 [pi-ai 包与源码](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/llm-pi-ai)和 [LLM 包](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/llm)。
2. **DeepSeek provider**：`@deepseek-ai/dsh-llm-deepseek` 是 transport／配置导出，入口组合为 `@deepseek-ai/dsh-llm-deepseek-api-key` 或 `@deepseek-ai/dsh-llm-deepseek-account`，二者 `inject=['llm']`。API-key 关联 launch-environment/credentials；account 可加 `@deepseek-ai/dsh-deepseek-account` 和 `@deepseek-ai/dsh-deepseek-account-platform`，后者硬注入 credentials、authorization，并涉及 Host Web 登录。不是仅挂 transport 就得到已认证 route。见 [API-key](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/llm-deepseek-api-key)、[account provider](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/llm-deepseek-account)、[账号平台](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/credentials/deepseek-account-platform)。
3. **凭据**：`@deepseek-ai/dsh-credentials` 是抽象服务，加载实现 `@deepseek-ai/dsh-credentials-local` 才提供 credentials；没有单独强制 inject 列表。实现引用 atomic-write、home-paths、launch-environment、chokidar、yaml、Schemastery；环境优先于管理文件，后接项目与 home 的 `.env`。见 [local 入口与包清单](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/credentials/credentials-local)。
4. **设置与 UI**：`@deepseek-ai/dsh-settings` 的 `static inject=['configEditor','profileContext']`；`@deepseek-ai/dsh-config-editor` 进一步 `['loader','profileContext']`，关联 app-boot/include、atomic-write 和 YAML。可选真实前端包为 `@deepseek-ai/dsh-client-ui-settings`、`@deepseek-ai/dsh-client-ui-settings-models`；后者客户端注入 slots/locale/remote、remote.credentials/llm/settings/session、configForms/settingsSchema。带 React 客户端、remotes、连接与 slot 代价，不能仅取一个模型页面就假设脱离产品壳运行。见 [settings](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/settings/settings)、[config-editor](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/boot/config-editor)、[models UI](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/ui-settings-models)。
5. **存储两种 medium**：`@deepseek-ai/dsh-storage` 为 hub；`@deepseek-ai/dsh-storage-domain`、`@deepseek-ai/dsh-storage-json`、`@deepseek-ai/dsh-storage-sqlite` 均 `inject=['storage']`。domain 用 zod/Schemastery，内存承载校验后的记录，写入持久后更新内存并发事件；跨进程变化不可自动见。JSON 的 single／per-record 由 domain spec 选择，SQLite 用同步 `node:sqlite`，均不需要会话产品才使用。当前 domain 无跨表事务、二级索引和通用迁移；SQLite 不改变这些上层限制。见 [storage-domain](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/storage/storage-domain)、[JSON](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/storage/storage-json)、[SQLite](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/storage/storage-sqlite)。
6. **任务**：`@deepseek-ai/dsh-jobs` 是抽象 seam，直接加载会抛错；`@deepseek-ai/dsh-jobs-local` 实现不单列 inject，引用 scope、timeout、agent/session 契约，继承 seam 的 workspace archive admission 事件。start 前必须有服务该 owner 的 controller；现成 `@deepseek-ai/dsh-tool-jobs` 的 `inject=['tools','jobs','systemPrompt']`，另关联 LLM/output-retention。可由业务代码 attachController，不必为此强行提供模型工具；按 agent owner 使用则需真实 agent/session。并发达到上限拒绝启动，不是排队。见 [jobs](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/jobs/jobs)、[local](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/jobs/jobs-local)、[tool](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/jobs/tool-jobs)。
7. **重试**：`@deepseek-ai/dsh-llm-retry` 的 `inject=['agents','sessionProjections']`，关联 agent、session、session-projection、LLM、timeout、zod；在 `agent/request-error` 瀑布处理失败 step，记录 retry 后再等待。需要实际 agent-loop 与持久会话组合才能获得其设计中的 durable step 行为。见 [retry 源码与说明](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/llm-retry)。
8. **编排**：`@deepseek-ai/dsh-workflow` 是引擎契约；实现 `@deepseek-ai/dsh-workflow-ptc` 的 `static inject=['subagents','ptcRuntime','sandboxPolicy']`，要求 TypeScript PTC provider（脚本正文为 JS），实际组合需 Node PTC、subagent、sandbox 与父 agent/session。`@deepseek-ai/dsh-tool-workflow` 的 `inject=['tools','workflowEngine','systemPrompt']`，还关联 jobs、session；程序调用 start 可省模型工具，但仍须 parent agent。文件 policy 不是网络限制，脚本／子代理限制与清理须按实际组合验证。见 [引擎实现](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/workflow/workflow-ptc)、[模型工具](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/workflow/tool-workflow)。
9. **自动触发**：`@deepseek-ai/dsh-schedule` 的 `static inject=['agents','sessions','tools','storageDomain','sessionController','sessionPersistence']`，关联 projection/workspace/Typert、Temporal polyfill、zod。可选组合包真实名称 `@deepseek-ai/dsh-experimental-schedule-bundle`。投递通过原 Session inbox + flush，再写 schedule domain，两次持久提交不是同一事务；需业务幂等。见 [schedule](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/schedule/schedule)、[experimental bundle](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/experimental/schedule-bundle)。
10. **MCP 消费**：`@deepseek-ai/dsh-mcp-client` 的 `inject=['tools']`，依赖 `@modelcontextprotocol/client@2.0.0`、Schemastery/values，并关联 scope、subprocess、timeout、LLM；资源与 systemPrompt 采用可选 child inject。图像结果需要 attachments。`@deepseek-ai/dsh-mcp-resources` 的 `static inject=['tools']`。外部工具执行仍通过 DSH tools 的调用上下文，不等于任意纯函数桥。见 [MCP client](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/mcp/mcp-client)、[resources](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/mcp/mcp-resources)。
11. **附件**：`@deepseek-ai/dsh-attachment` 是抽象存储契约，`@deepseek-ai/dsh-attachment-local` 提供实现，没有单独 inject；引用 home-paths、lazy-require、Schemastery 和 Sharp。generic file 保持字节，image 有归一化／缓存；该后端按内容寻址计算 digest 是其特定存储设计，不应扩成项目所有文件通用哈希关卡。见 [local store](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/attachment/attachment-local)。
12. **Office PDF**：`@deepseek-ai/dsh-office-to-pdf` 的直接 convert 不要求 workspaceFiles/fs，主要依赖 `@deepseek-ai/libreoffice-kit@0.1.1`、Schemastery、Typert、brand、zod；浏览器 remote render 才读取 workspaceFiles 和 fs 服务来授权和读源文件。声明支持 DOC/DOCX/XLS/XLSX/PPT/PPTX；目标平台声明原生引擎但未安装时不会偷偷退回 WASM。见 [转换入口、包清单和平台边界](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/document/office-to-pdf)。
13. **会话／workspace 支撑**：`@deepseek-ai/dsh-session-persistence` 为契约，`@deepseek-ai/dsh-session-persistence-jsonl` 为实现，关联 `@deepseek-ai/dsh-session`、LLM、session-format/catalog/迁移组件、node-addon-system、koffi。不列单独 inject，但通过 session 事件接 live write；flush 才是 seam 的持久屏障。`@deepseek-ai/dsh-workspace` 的 `static inject=['storageDomain','sessionPersistence']`，并关联 session、storage、Typert、brand/zod。其目录和 Session 分组可复用，作品／译文／术语实体另建业务 schema。见 [JSONL backend](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/session/session-persistence-jsonl)、[workspace](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/workspace/workspace)。

## 选型建议

先把已实跑的模型组合，以及 credentials、storage 两种 medium 列为近期重点；附件与 Office PDF 按实际输入输出选用。若采用 DSH Web/agent 产品结构，settings/model UI、session/workspace、jobs、retry 就有共同复用收益，可以按组合比较，不要求逐包脱离依赖证明“独立可用”。workflow 留作多步骤执行候选，schedule 跟随 P2 自动触发范围。

无论选哪条组合，DSH 没有由上述插件直接提供本项目的术语组合、译文复用键、已接受译文、同源多输出、翻译单位 checkpoint 或原生文档译文回填。下一步应在实施对应功能时做一个实际业务小闭环，优先验证存储边界、取消后提交和恢复；本轮仅更新候选与复用判断，不新增逐插件实验任务。

DSH 固定源码与所核验包清单为 MIT，但 Sharp/libvips、LibreOffice kit 的引擎和传递依赖分发通知需按最终选用闭包处理；不据顶层 MIT 推断所有嵌入引擎许可。DSH 仍是 developer preview，固定源码核验不代表 npm 已发布状态或各平台二进制可用性。
