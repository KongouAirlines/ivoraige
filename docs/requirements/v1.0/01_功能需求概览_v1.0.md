# 通用翻译中间层：功能需求与分阶段优先级

版本：v1.0｜2026-09-29｜需求与优先级基线

## 项目目标与背景

目标：做一套可按需组装的通用翻译工具与中间层。以科研英汉为首个应用，通过复用现成组件覆盖文档、书籍、网页、截图和独立文本；为其他语言与文学场景保留扩展能力。

项目首先希望解决**同一文本在不同类型翻译任务中重复翻译**的问题。在希望串联的使用流程中，MinerU、Docling 等解析工具用于形成可供 RAG、LaTeX 等后续处理的内容，PDF2zh 类工具用于生成尽量保持原排版的译文 PDF。若两条流程各自完成正文翻译，同一内容就会被重复处理，造成时间与资源浪费。因此，希望解析、重排与不同输出任务能够复用同一份译文。

其次，希望解决**术语库难以跨任务复用，以及自动选择与切换不便**的问题。当前使用场景中的建库方式包括手动录入、在线服务和各工具独立的 LLM 建库流程。在 PDF2zh 等翻译任务中形成的术语库，需要能够继续迁移、复用于其他翻译任务，而不是随单次任务结束而难以利用。项目希望把自动建库、知识管理、跨任务复用与按文本需要选择词库连接起来。

## 本版定位与使用方式

本版以用户修改的 `01_功能需求概览_v0.5(1).md` 为依据，保留 **F-01～F-44 共 44 项功能期望**及三大分类，将已填写的优先级和备注合并为当前基线。未填写调整的条目沿用 v0.5 原建议；本次不再重新定级，也不增加功能编号。

**v1.0 指需求文档版本，不代表软件已发布，也不代表 44 项功能必须在首批同时完成。**本文明确功能期望与分阶段范围，具体选型、接口和实施拆解留待后续规划。

主表使用「当前优先级」「阶段与范围说明」「后续调整／备注」。已有意见已经落实，不再并列展示一份旧建议与一份待采用的调整；需要继续修改时，可直接改当前优先级，也可填写最后一栏。

| 级别／标记 | 含义 | 条目数 |

优先级表示相对先后，不表示工期、难度或交付日期。表中统计按条目的主标记计算；一个条目的后续扩展范围不因此全部提前。F-30 的自动触发、F-07 的更多格式等沿用原有分阶段说明，见对应行。

| F-43 | **协作交接与审校意见**：允许将选定章节、段落或项目交给他人审校，保留评论、修改建议及处理结果。暂列远期，可先通过文件交接；实时多人编辑、账户体系和自建协作服务器不作为近期前提。 | **P3** | P3 远期保留；简单文件交接可使用现成工具，不以建设多人在线服务为近期前提。 |  |

### 3.4 统一外部操作入口

| 编号 | 功能期望 | 当前优先级 | 阶段与范围说明 | 后续调整／备注 |
|---|---|---|---|---|
| F-28 | **OpenAI 兼容入口**：将本项目翻译能力包装为 OpenAI 兼容服务，供允许配置自定义接口的未适配软件或闭源软件使用。 | **P1** |  |  |
| F-29 | **可扩展 MCP 基座**：提供统一 MCP 基座和插件接入接口，各功能插件按需注册或撤销自己的能力，由基座统一对外暴露，供用户现有 harness 调用；它只是额外操作入口，不替代其他功能或界面。 | **P1** |  |  |

MCP 仍是一个统一基座：功能插件通过基座接口按需注册能力，供用户已有 harness 调用。它只是额外操作入口，不替代其他功能，也不要求模块之间都改用 MCP。

## 分阶段范围与条件项

以下将同一宽泛需求中的基础部分与后续扩展分开说明。它与上方主表采用同一优先级口径，不新增任务编号，也不构成工期承诺。

| 范围 | 先行或近期范围 | 后续范围与条件 |
|---|---|---|
| 核心翻译：F-01、F-03、F-05、F-11、F-13 | **P0**：插件式组织、用户设置、基础文本翻译、建库／翻译模型分别配置，以及同一译文跨流程复用。 | 更复杂的自动流程选择仍按 F-33 的 P2 推进。 |
| 知识建设与使用：F-14～F-18 | **P0**：小规模指定语料建库、知识编辑和项目库组合。**P1**：完善分类检索与暴露设置。 | 大规模持续建设与更复杂分类，随实际语料扩展。 |
| 词典与外部术语服务：F-40 | **P1**：接入用户需要的可调用词典或术语来源，在建库、翻译和审校中使用。 | 保留本地与在线两条路线，不要求接完全部来源；本版不再将 F-40 列为 P0。 |
| 本地模型与资源：F-27、F-04、F-34 | **P0**：将已有本地服务作为模型接口接入。**P1**：完善按需运行、启停与管理。 | **P2**：按流程提前预热，并利用启动耗时优化加载、保留和释放。 |
| 任务与批量使用：F-30 | **P0**：进度、取消等基础任务操作。**P1**：暂停和恢复。 | 文件夹监控、外部事件自动触发沿用 **P2** 的安排，不要求基础任务功能等待全部触发方式完成。 |
| PDF 与原生输出：F-06、F-07 | **P0**：一条论文 PDF 路线及复用相同译文的 Markdown／JSON。 | DOCX、基本双语成品及已有 LaTeX 源稿往返按 **P1** 关注；更多 EPUB／编辑工程按 **P2** 扩展。LaTeX 往返不等于从 PDF 反建源码。 |
| 整书与输入校正：F-08、F-09、F-41 | **P1**：选定范围处理、基础拆分合并与书签、可查看和修正的解析结果。 | 复杂跨页关系与特殊版式，随后端能力逐步补足。 |
| 人工精翻：F-20～F-22 | **P1**：单人使用的两种精翻状态、双语编辑、局部审校与全篇一致性检查。 | 不以实时多人编辑、自建协作站点或企业管理平台为前提。 |
| 成果积累：F-31、F-32、F-37、F-39 | **P1**：保存修改、增量处理与迁移，复用翻译方案，导入既有译文，并进行小样比较。 | 自动整理作品风格与个人偏好，按 F-19 的 **P2** 推进；不等同于训练模型。 |
| 客户端与外部入口：F-23～F-26、F-28、F-29 | **P1**：选择少数现成网页／OCR／文献客户端，并提供公共 MCP 基座和 OpenAI 兼容入口。 | 更多 CAT 或商业工作台接入按 F-26 的 **P2** 推进；不因提供接口就建设公共托管平台。 |
| 新载体与参考：F-35、F-36、F-42、F-44 | **P2**：视觉小说、漫画、图文辅助与已有字幕翻译，作为可选方向保留。 | **字幕自动生成→翻译**保留为后续扩展意向，具体范围和优先级尚未单独确定；不据此新增语音处理模块选型。 |
| 多设备：F-38 | **条件式 P1～P3**：若已采用前后端分离或 Web UI，可将多设备操作顺带提前；否则视实现条件延后。 | 不为提前此项而单独扩大为公共服务器、多机集群或完整托管平台。 |
| 多人交接：F-43 | **P3**：协作交接与审校意见保留为远期，简单文件交接可使用现成工具。 | 实时多人编辑、账户体系、自运行协作服务器等，待需求明确后再规划。 |

## 当前不定死的内容
