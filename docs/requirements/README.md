## 架构决策与阅读分工

- **架构决策记录（ADR）**：[ADR-0002](../decisions/0002-plugin-composition-0.1.0.md) 规定已采纳的插件组合与能力归属原则；[ADR-0001](../decisions/0001-runtime-selection.md) 保存早期运行时选型与实验依据；[ADR-0003](../decisions/0003-runtime-migration-gate-0.1.x.md) 明确运行时迁移的双条件门禁。
- **版本与编号约定**：新活跃计划和设计统一按目标软件系列 `0.1.x` 组织，原 [design-v3](../plan/follow-ups/design-v3.md) 作为稳定事项 ID 保留，不新建并行的 `v3` 文档编号体系。
- **三类信息来源互不替代**：
  - 判断“**现在能做什么**”：看 [0.1.0 能力表](../plan/0.1.0/capabilities.md)与相应用户指南；
  - 判断“**接下来做什么**”：看 [0.1.x 工作包索引](../plan/0.1.x/work-packages.md)；
  - 判断“**过去验证了什么**”：看带日期及提交哈希的 [0.1.0 阶段记录](../plan/0.1.0/README.md)。
- **维护约束**：保留原需求 ID、章节锚点和固定提交证据，不为整理目录改写历史报告。修改当前协议必须在同一实施 PR 中同步更新代码、测试、兼容说明与对应文档；规划目录调整本身不修改 `API_VERSION` 或持久化 schema 版本。
