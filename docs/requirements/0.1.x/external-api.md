# 0.1.x 可调用翻译方案与共用外部 API 草案

本页定义共享接口与方案管理，并细化 [#41](https://github.com/KongouAirlines/ivoraige/issues/41) 的 OpenAI 适配及 [#42](https://github.com/KongouAirlines/ivoraige/issues/42) 的 KT 接入契约。基础边界见 [contracts](contracts.md#稳定对外接口与可调用方案)，保存与冻结模型见 [workflows](workflows.md#可调用方案与集中管理)。实施切片和上游依据见[专项路线](../../plan/0.1.x/external-api.md)，验收见[外部调用矩阵](../../plan/0.1.x/validation/external-api.md)；版本范围与执行状态仍分别由 releases、工作包索引维护。

## 当前起点与责任

现有 [HTTP](../../../src/http.mjs)、[MCP](../../../src/operation-mcp.mjs) 已共用 [Operations](../../../src/operations.mjs)；这是复用起点，不表示已有方案发布或下述端点。P04 负责内部 operation 注册及公共调用边界，W01/W02 负责组合定义和保存冻结。新增外部 facade 选择稳定子集并收窄输入/授权，不从内部注册表自动生成全量公开接口。

```mermaid
flowchart LR
  CLI[owner CLI] --> Publish[I01.callable@1 发布服务]
  UI[W03.publish-ui@1 后置管理界面] --> Publish
  Publish --> Saved[W02 保存定义与发布投影]
  Native[原生 HTTP / MCP] --> Facade[同一受约束调用服务]
  OpenAI[OpenAI 兼容适配] --> Facade
  KT[KT provider 插件] --> Native
  Saved --> Facade
  Facade --> Ops[P04 公共操作]
  Ops --> Domain[工作流 / 术语 / Records / tasks]
```

主体服务只认识公开契约和方案身份，不按客户端名称分支。协议插件拥有传输、消息映射和 disposer；同进程 OpenAI/MCP 可直接调用该 facade，无需绕回 HTTP。不同协议仍使用同一配置解析、术语、复用、任务和错误源。先维持原生契约与 OpenAI 兼容子集两类对外形状，新增软件优先映射原生契约，只有真实能力差异才扩展契约。

## 发布投影与运行绑定

以下名称和路径是待实施评审固定的候选，不修改当前 `API_VERSION`。宿主版本、原生 API 版本、方案配置修订、插件 SDK 版本彼此独立。

| 对象 | 语义与权限 |
| --- | --- |
| 方案 `planId` | 稳定不透明 ID、显示名、说明、发布状态和可调用能力；名称可改，ID 不复用给另一方案。仅授权者可发现、描述或执行 |
| 发布修订 `planRevision` | 指向 W02 WorkflowInstance 的确切修订（项目关联可为空，仍有所属访问域），包含绑定及允许覆盖字段的 schema/限额、输入输出 profile、语言政策、最终输出选择和授权发布范围；不复制节点/边定义 |
| 绑定 | 模型/连接引用、术语库版本、抽取配置版本及其他有效约束；发布前解析可继承默认并显示来源。秘密仍由 DSH credentialRef 提供，不进入描述、导出模板或运行快照 |
| 运行 | 受理时原子解析已发布修订、校验调用权限和覆盖项，冻结 W02 RunDefinition，并分配 runId；关联原输入 ID、实际约束版本和任务。无需先创建长期项目，也不能让无项目调用越过数据所有权检查 |

草稿编辑 → 测试 → 发布形成新修订；测试明确标注使用草稿修订，同样提示费用/外发并保留运行证据，不伪装成正式调用。稳定 ID 默认解析当前发布修订；原生请求可指定确切修订以便重现配置。旧修订只有仍被明确开放时可新调用，撤销不会因猜到修订号失效。发布新版本、变更默认或更新词库均不重写在途/历史运行；需要新词库版本时重新解析、测试并发布，不把“最新版”悬空引用带进冻结定义。

撤回发布停止新调用，历史记录保持可读（仍受原权限约束）。单独撤回发布可让已受理运行按冻结配置收尾；撤销客户端授权则立即按[单机授权](contracts.md#单机客户端授权)拒绝后续调用/调度、关闭流并请求取消。配置冻结不保留已撤销权限。缺失模型、词库版本或插件时标 unavailable 并给原因，不改用另一模型。并发请求各持自身绑定，禁止通过修改全局当前模型/词库来调度。

## 原生外部接口

候选前缀 `/api/external/v1` 与当前内部操作入口区分；最终名称在首个实现 PR 固定并附兼容说明。MCP 将同一组语义映射为受限工具，不发布任意 invoke 工具给外部客户端。凭据来源、principal、scope、逐调用校验、撤销与旧入口门禁以[单机客户端授权](contracts.md#单机客户端授权)为唯一基础定义；本节只映射协议。

| 候选操作 | 最小语义 |
| --- | --- |
| `GET /service` | 服务实例身份、原生 API/宿主版本、协议能力；要求 service.read，能力按授权投影；未认证不返回实例/方案描述 |
| `GET /plans`、`GET /plans/{id}` | 调用者可见的已发布方案及修订、输入输出 profile、语言、可覆盖 schema、批次/大小限额、成本/外发说明、可用状态；不返回真实模型配置、凭据或私有流程内容 |
| `POST /runs` | 接收 planId、可选修订、items、语言、受限上下文/术语/overrides，验证后受理并返回 runId/解析修订；客户端请求 ID 与服务器 runId 分离 |
| `GET /runs/{id}`、`GET /runs/{id}/result` | 任务状态、输入 ID 对应结果/错误、实际方案修订、usage 状态与诊断关联；读取权限与创建授权关联，猜到 ID 不能跨调用范围读取 |
| `POST /runs/{id}/cancel` | 幂等提出取消，返回请求已受理或任务已终止的真实状态；不把请求取消等同供应商未收费 |
| 方案范围内的术语查询/候选操作 | 只查询允许使用的有效约束摘要或限定词项；抽取候选另需能力与费用授权。共享库写入走独立确认及写权限，不给普通翻译令牌全库导出/修改权限 |

### 协议授权映射

HTTP 原生、OpenAI 入口使用 Authorization: Bearer；HTTP-MCP 在连接及每次请求验证同一凭据。受限 stdio MCP 由可信 owner 启动配置绑定 grant，客户端不能通过工具参数指定 principal；调用上下文传入同一 facade。不在 query、items、messages 中接受令牌，不将上游供应商 key 当作入站凭据。

| 表面 | 公共 scope 与对象检查 |
| --- | --- |
| /service | service.read |
| /plans、/plans/{id}、/v1/models | plans.read，过滤授权方案与修订；OpenAI 再过滤文本/语言兼容 profile |
| POST /runs、/v1/chat/completions | runs.create，校验方案修订、资源/库范围和允许覆盖；同步或流式返回该次结果还须 runs.read；响应元数据绑定服务端 principal/runId |
| 状态、结果、运行事件及重连 | runs.read，检查运行归属；使用同一凭据重新鉴权，不因已有流/幂等键跳过撤销 |
| 产物下载 | artifacts.read，加运行/产物范围检查；无公开匿名文件 URL |
| /runs/{id}/cancel | runs.cancel，加运行归属；读权限不自动包含取消 |
| 术语查询、抽取候选、确认写库 | 分别 terms.read、terms.candidates.create、terms.write，检查库/来源范围及显式确认；抽取费用另校验 |

MCP 工具/资源映射逐项复用以上 scope；协议插件不能直接调用宽权限内部 operation 省略 facade。owner 的签发/撤销、发布配置等管理不出现在普通客户端工具列表。正常翻译客户端的授权说明应列出所需读/执行/取消等 scope，不用一个隐藏的全权 token 省事。

请求示意（字段候选，原生 JSON，不是第二工作流格式）：

```json
{
  "planId": "academic-zh",
  "planRevision": "r3",
  "items": [{ "id": "p17", "text": "A source paragraph." }],
  "textFormat": "text",
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN",
  "context": { "text": "Nearby text only", "coverage": "fragment" },
  "overrides": {}
}
```

items 的 ID 在本请求内唯一且保持不透明字符串；结果严格对应输入 ID，保留输入顺序，不用结果数组位置猜映射。描述声明批次数、单项/总字节、上下文长度及超时限额；超限在付费调用前拒绝，客户端显式拆批，不静默截断。空输入、重复 ID、未知 profile/覆盖项返回字段错误。批量部分失败时逐项报告并给整体状态；只有所有必需项通过最终校验才能声称整批成功。公开结果不自动移动已有文档 accepted，若方案有自动接受政策，须作为独立显式发布条件及并发校验评审。

只允许已声明的 `text` / `html` profile；HTML 使用结构约束保留允许标签/占位符，既不执行脚本也不由服务抓取页面资源。标题、URL、上下文都是有大小限制的非可信数据，URL 不授予读取权限，也不触发自动下载；缺全文时标 fragment/unknown，不假造整页上下文。服务侧模型输入拼装继续遵守领域约束，不直接把客户端提示词当最高权限指令。

执行接口复用 tasks 的权威状态。原生连接断开不抹去已受理任务；客户端通过 runId 查询或显式取消。适配器可声明请求级取消策略及 deadline，但不能把网络断开视为已成功取消；超时、供应商执行未知与可安全重试分别表达。幂等键按调用主体/授权域隔离：首次受理绑定规范化请求、方案修订及 runId，同键同内容返回原运行，不重新解析最新方案；同键异内容冲突。保留期与过期后行为在首个切片公布，不承诺跨任意时间 exactly-once。结果/原文/诊断沿用宿主保留策略，敏感正文不默认进入日志。

## 术语与抽取配置

术语后端由 [U03.terms@1](../../plan/0.1.x/packages/ui.md#u03-terms)交付，I01.callable@1 消费其已验收版本；管理页不是前置。术语语义继续由[补充 0001](../amendments/0001-term-applicability.md)及[terms / termBuilder 职责](contracts.md#术语服务与翻译复用)定义。客户端不重复实现义项与适用性规则，方案绑定中央可复用库和抽取配置，显示实际范围与版本。

候选优先政策：先按语言、来源/领域/义项适用范围筛选，再在适用候选中按方案库优先级解决。请求 glossary 默认为本次候选约束；与中央有效术语冲突时返回冲突，或按方案**显式允许**的 request-overrides 政策仅在本次覆盖，同时记录来源和最终取值。请求覆盖不能扩大适用范围、绕过被锁定条目或变成长期库优先级；无法证明适用性时请求核对或拒绝，不猜义项。

抽取候选、选择本次使用、确认写共享库分别授权并留痕。普通外部翻译可以使用已发布有效约束；如果方案启用抽取，说明其模型/成本、输入范围、版本和是否仅生成候选。新候选默认不立即作为已确认共享约束；无需人工等待的方案只能使用已确认库或明确允许的本次临时候选政策，不能暗跳共享库确认。全文抽取需要完整且获准的来源交接；零散请求只能产生对应片段范围的候选。约束版本变化参与复用判定，不因输出文字相同而忽略来源或版本。

## OpenAI 兼容投影

这是向外提供兼容服务，与使用 DSH 调用上游 OpenAI 模型方向相反。首个 profile 面向确定输入的文本翻译，参照 [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create/) 与[流式事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events/)的 wire 形状；以下支持范围是本项目候选子集，不表示通用聊天能力已实现。

| 表面 | 候选约束 |
| --- | --- |
| `GET /v1/models` | `data[].id` 为授权且已发布的文本兼容 planId，按标准模型列表形状返回；显示名、修订、语言和能力详情用原生描述获取。真实底层模型不作为列表项 |
| `POST /v1/chat/completions` | `model` 选择方案；首轮接受单条 string-content user 消息作为待翻译正文。可选 system/developer 文本仅在方案明确允许的 instructions profile 下成为受限风格/上下文；未开放时明确报错。多轮 assistant/tool 历史、多模态、tools、任意 response_format 等未支持项拒绝，不静默拼接或忽略 |
| 语言 | 普通兼容客户端优先选择固定目标语言方案；可选原生扩展字段用于方案允许的语言覆盖。无固定目标且客户端不能传扩展时，该方案不进入此入口列表。不从任意自然语言 system 提示中猜目标语言或改中央配置 |
| 参数 | temperature、输出限额等仅在方案 override schema 允许时映射；不能借 `model`/额外字段覆写真实模型、连接或词库。固定为单个结果 `n=1`；未知或越界参数给明确错误，不能假装执行 |
| 单段与批次 | 默认 user 内容全部视为一个原文项，形似 JSON 也不自动升级为控制信息。批次需另一个显式声明的 batch-json profile，输入/输出中保留每个 ID；客户端必须按该 profile 编码。原生批次与 KT 原生桥接无需把 ID 塞进自由提示词 |
| 结果 | assistant content 是所选方案的最终文本，响应 model 保留方案 ID；原生 runId/实际修订通过受控响应元数据或请求关联查询。人工等待、二进制结果、需外部写回确认的流程不进入兼容列表 |

首轮允许先完成非流式。只有通过最终术语/结构检查后不会再被改写的内容才能作为 content delta 发出；可先缓冲整份最终结果再按块传输，不把模型草稿、推理、抽取候选或进度冒充译文。结束成功时发送合法终止 chunk 和 `[DONE]`；截断、部分失败或取消不得发送成功终止。客户端不能仅凭收到部分文字视为成功，结果查询仍以权威运行状态为准。请求断开时兼容层尽力取消并保留查询线索，供应商可能已经执行/收费。

usage 取自实际运行，不按输入长度伪算。多阶段调用分别保留明细；只有计量单位与涵盖阶段可解释时才汇总至兼容字段，部分未知则不伪报完整总量。缺 usage 采用省略/null 的已测客户端策略，绝不填 0 充数；请求 `include_usage` 的最终 chunk 只有完成时才能可靠提供，截断可能没有最终 usage。不同模型 token 统计的汇总含义需描述，不冒称某个真实模型的完整计费。

请求字段/不支持功能映射 400，未认证 401、权限不足 403、获准范围内未找到资源 404；无权对象统一 403，不探测存在性，冲突 409、大小 413、配额 429、能力暂不可用 503；上游失败/超时保留可诊断的错误类型，不全部变成空成功。沿用公共错误源，仅调整兼容 envelope，已开始 SSE 后以明确错误/非成功关闭表达；不泄露供应商凭据或内部栈。401/403 及对应机器语义遵循基础契约；兼容 envelope、未知 usage 客户端容忍度及 batch profile 在实现验收固定。

## 管线管理与客户端互认

管理入口放在现有“软件联动”页内的“可调用方案”，并从工作流保存页进入同一管理器；不另增设置标签或复制配置。I01.callable@1 先提供 owner CLI 准备/发布路径；W03.publish-ui@1 后接同一服务，以列表/表单提供保存、复制、配置、测试、发布/撤回，显示当前草稿与发布修订差异、类型/语言/外发/费用、锁定与允许覆盖字段、使用哪些词库/抽取配置。模型对象仍由模型页管理，库由术语页管理，全局并发/连接安全策略仍归设置；编辑方案只保存引用和本次配置，遵守 [UI 三层归属](ui.md#三层归属与设置标签)。

客户端输入服务地址及授权凭据后，握手核对实例身份、API 版本、能力及允许方案，再保存客户端标识用于诊断和授权关联。实例身份变化须确认，不能凭同名服务自动重连或无授权扫描局域网。clientId 和显示名均是标签，认证与授权由[单机契约](contracts.md#单机客户端授权)映射的 principal/grant 决定；不得复用上游模型或 Zotero 密钥。owner CLI 签发不依赖 W03/U02 UI，后续设置入口使用同一管理服务。

保留 HTTP Host/Origin 校验，按明确 origin 授权；不因“本机”放开 CORS。撤销凭据、撤回方案、插件禁用各有独立影响，记录授权范围和恢复动作；不将 KT 本地插件授权等同 ivoraige 的执行授权。公开接口扩展采用版本化描述和已支持字段，不以任意透传字典绕过校验。

## KT 薄桥接

KT 负责页面提取、分段、批次组织及渲染；provider 插件只选择方案并映射原生请求/结果。插件实例保存服务地址、客户端凭据引用、方案选择及必要传输选项，模型/词库/抽取规则集中维护。若采用脚本处理原生异步任务，只实现协议调用、等待与映射，不复制业务编排；是否用声明式规则取决于固定 KT 版本的表达能力。

| KT 输入/行为 | 原生映射与限制 |
| --- | --- |
| items / id | 保持本次所有 ID 与顺序；缺失、重复、额外结果或空译文明确失败。KT 聚合/并发与宿主配额分别控制 |
| sourceLanguage / targetLanguage、textFormat | 规范化受支持语言代码并校验方案；HTML 结构约束独立验收，不仅测试纯文本 |
| glossary | 转为本次术语候选约束，按中央方案冲突政策处理；不重复本地替换造成二次改写。联调记录 KT 替换引擎启停状态和实际先后顺序 |
| context / tone / document title、url 等 | 有限上下文与来源元数据，不保证全文、不自动抓 URL；缺失上下文可按描述降级或明确拒绝依赖全文的方案 |
| systemPrompt / userPrompt | 仅映射方案允许的 instructions，否则报告不支持；不能绕过中央术语/格式约束或伪称全部 KT 提示词能力已支持 |
| streaming / cancel | 只发最终稳定内容及合法 item ID，始终返回完整最终结果；SDK 取消/Worker 终止可能使显式 cancel 无法送达，服务侧用有界 deadline 和结果查询收尾，不能报告取消已完成 |

实际支持版本、安装/授权和更新语义见[KT 证据与交付](../../plan/0.1.x/external-api.md#kt-证据与交付)。OpenAI 包装是通用客户端兼容路线，KT 验证优先用原生方案能力，不等待 OpenAI 包装；KT 与 Zotero 同级高优先、可并行联调，实际端到端验收再满足各自必需的共享能力。两种协议共用服务，不为 KT 再造业务 API。
