# ivoraige

**供人和 AI 共用、可自由组合的翻译与文件处理基础设施。**

把需要的工具放进同一个工作空间，完成翻译、审校和后续文件处理。

ivoraige 将分散的翻译和文档工具组合成可以按需选择的工作流。面向学习者、学生、科研用户，以及为爱发电的翻译者，涵盖学习笔记、论文、小说和日常阅读等场景。

我们希望为人和 AI 提供共同的基础：选用需要的能力，审阅处理结果，让已有工作在不同工具和输出格式之间延续。

## 组合适合自己的流程

- **按需增加能力。** 从文本和 Markdown 开始，需要处理 PDF 时再安装可选组件。
- **保留人工判断。** 对照原文与译文、保存草稿、接受修订，随时继续已有工作。
- **复用已接受译文。** 从同一冻结快照导出支持的格式，导出不会再次调用模型翻译。
- **保留原文结构。** CLI 使用 `--content-mode source` 可在没有目标语言或已接受译文时导出 Markdown/JSON；已导入的 PDF 也可复制经过校验的受管原件。默认仍需 `--target-lang` 导出已接受译文。
- **需要时指定实现。** `--format` 表示文档或输出格式，`--adapter ID` 显式指定已安装的适配器。未指定时按兼容输入视图的最高匹配分选择，同分需要显式选择。排队任务固定所选实现及版本，期间变化则报错并提示重试。只接收文本的实现不会替代处理 PDF 文件或二进制上传所需的可选组件。
- **选择使用方式。** 使用浏览器工作台、CLI，或通过 [MCP](docs/plan/0.1.0/mcp-guide.md) 将 AI 客户端连接到共享内核。
- **保存前纠正设置错误。** 模型兼容开关若不适用于路由中任何模型的协议，或推理参数无效，会按输入错误返回；CLI `settings --set` 的 JSON 格式错误或非对象根值（如 `null`、数组）在本地和远程模式均返回 `INVALID_ARGUMENT`，退出码 2。

## 开始使用

**从源码运行 0.1.0。** 按[安装指南](docs/plan/0.1.0/installation-guide.md)准备并启动。此前的 Release 及附件已撤下，预构建下载包延后提供。源码仓库现已公开。

需要 Node.js `>=24.22.1 <25 || >=26.12.1 <27` 和 npm。源码运行可使用这两个受支持主版本内更新的稳定补丁版；Node 25 和未来主版本暂不在支持范围内。Windows 便携包构建固定使用 Node.js 26.12.1。

1. 打开工作台，导入 TXT 或 Markdown 文件。
2. 需要机器翻译时配置模型，也可以直接录入自己的译文。
3. 审校并接受修订，导出结果。

处理 PDF 时，先按 [PDF 开发参考](docs/plan/0.1.0/pdf-development.md)准备 Windows 可选环境，再按 [PDF 指南](docs/plan/0.1.0/pdf-guide.md)操作。默认在线组件源目前没有可下载的 Release。

配置、调试与贡献代码请看[开发指南](docs/plan/0.1.0/development-guide.md)。详细指南目前以中文为主。

组件安装与文档任务共享有限后台任务配额。安装期间受理的文档任务排队等待；文档任务执行时提交安装会提示冲突，可在任务结束后重试。

### 适配器可用性与可读输出

缺件来源仅根据声明格式和兼容输入类型分类，不执行 matcher。JSON/Markdown 可读导出要求来源显式提供 `readableText` 投影；TXT 和 Markdown 声明原样投影，不请求来源视图的二进制输出仍独立可用。输出枚举与选择共用可用性规则，并可传入内容模式：disabled/failed 输出不可用，unavailable 输出仅可通过 `canRunUnavailable` 明确允许特定模式。显式输出版本必须是非空字符串，省略版本仍兼容为 `unversioned`。

进程内调用的显式输出版本约束会在导出受理前及执行时校验。恢复任务时，先按冻结快照的来源绑定、来源版本信息、内容模式及持久化适配器/版本检查尚未完成的输出，再将 paused/failed 改为 queued；已完成产物保留检查点，无需重新安装其原输出适配器。来源导入的发现、自动/显式选择和排队执行统一排除 unavailable、disabled、failed 状态。

## Q02 任务与导出文件保留

失败任务仍可重试，也会保留它引用的导出快照。需要放弃重试时，明确执行 `abandon TASK_ID`：状态变为 `abandoned`，原错误与任务历史仍可查询；`cancel` 不能代替该操作。排队、运行或暂停中的任务不能放弃。

`artifacts DOC_ID delete ARTIFACT_ID` 默认只删除产物记录，并返回保留文件的 `retainedPath`；显式 `--out` 文件以及没有归属标记的旧产物只能这样处理。只有确定要删除内核默认导出目录中的受管文件时，才加 `--file-action delete-owned`。内核会核对目录归属、原文件摘要、其他产物引用以及任务和读取租约。删除失败后，使用 `artifacts DOC_ID cleanup` 查找持久清理记录，排除原因后对原产物 ID 重试相同的删除命令；清理完成前不能复用该路径或释放相应快照。已经删除的文件只能从自己的备份恢复。

HTTP 和 MCP 有相同语义；参数、恢复步骤及备份边界见[开发指南](docs/plan/0.1.0/development-guide.md)。首次 Q02 写入只把受影响文档标记为 schema 3；旧程序会在存储单元版本检查时拒绝打开升级后的库。要退回旧源码，须恢复写入前的完整 SQLite 备份及相关文件，不能只退回程序代码。本阶段没有迁移真实用户库。

新建库将 DSH ivoraige_records 存储单元标为版本 2。已有版本 1 库仍可读取和进行普通写入；首次所有权、清理或 abandon 写入前，内核先同步将存储单元标为版本 2，再保存对应的 schema 3 记录。其他文档不会被批量改写。旧程序随后会在打开库时因单元版本不匹配而拒绝，不能只退回程序代码；需要恢复写入前的完整 SQLite 与导出文件备份。即使记录保存失败，单元也可能已升为版本 2，这是阻止旧程序写回的保守状态。

进程内宿主现可在 `operationCatalog` 中注册一份 schema/handler，并持有注销句柄；现有 CLI、REST、MCP 别名及内部通用操作入口均委托该注册。HTTP、CLI、MCP 可独立省略。现有工作台通过订阅 ready 屏障后重取权威状态，产物读取共用归属、大小策略和读取租约。见[组合用法](docs/plan/0.1.0/development-guide.md#p04-operation-and-entry-composition)及 [P04 验证记录](docs/plan/0.1.x/evidence/foundation-p04.md)。

提交任务或长时间执行的操作使用通用 CLI `call` 时，需要持续宿主（`--url` 或调用方提供的 app）；自建本地宿主会在创建工作前拒绝调用。本地可使用既有 CLI 别名等待任务完成并取得最终退出码。
**0.1.x 入口与资源可用性。**

`delete-owned` 需要资源访问和导出服务。缺少任一服务时，调用会在修改制品记录或建立清理标记之前返回 `COMPONENT_MISSING`；仅删除记录仍可由 Records 服务执行。MCP 会列出已经注册的工具；所需服务尚未挂载时，调用返回 `COMPONENT_MISSING`，服务就绪后同一工具可调用。`events: false` 仅关闭新的状态流，旧版 `/api/events` 任务流和远程 CLI `--json-events` 仍可使用。`components`、`exportDir` 和 `maxArtifactBytes` 配置需要 `store`。

### 共享产物文件身份

物理删除受管文件时，文件符号链接按完整规范目标计入共享引用，即使链接位于另一目录或使用不同文件名。无法确定目标的悬空链接会保守阻止物理删除。默认只删记录仍保留文件，且不要求文件系统身份查询。目录别名及实际卷的大小写语义继续保留；外部输出文件、链接路径本身不因此获得受管删除权限。既有外部并发替换边界不变。

操作目录晚挂载后，注册或撤销操作也会推进状态版本并通知订阅客户端；目录撤销或状态桥关闭时释放对应监听。导出发现与受理共用来源视图相容性检查：所选输出的 `requiredViews` 需要文档绑定的来源适配器、兼容的实现/schema 版本及声明的投影方法。缺件返回 `COMPONENT_MISSING`，版本或投影不相容返回 `PRECONDITION_FAILED`，均在创建快照或任务之前拒绝。全局格式描述已安装能力，文档 `availableOutputs` 和状态摘要按该文档冻结来源筛选；当服务齐备且至少一种输出在支持的内容模式下可用时，`exportDocument` 才报告可用。`requiredViews: []` 的输出仍可在无 Parse 时使用。受理成功后才撤销组件仍可能导致执行失败，失败任务保留冻结快照供恢复后重试。公开输入格式列表统一将 `markdown` 规范化为 `md`。

### 组合宿主中的任务读取

Operations 可以先于 Records/Tasks 挂载。所需服务完成挂载后，即时任务查询及等待会使用请求开始时的 Records，并在该次等待内保持同一存储实例。缺少所需服务仍返回 COMPONENT_MISSING，默认 createApp 挂载顺序继续支持。

### MCP 请求取消

MCP HTTP 任务轮询断连会释放该请求的订阅，不取消持久任务。MCP HTTP 边界独立持有原生 Node 请求生命周期，不依赖 SDK Request.clone 的信号转发；并行轮询互相隔离。正常请求体读完不代表响应断连。独立 createMcpHttp 处理器遵循同一归属规则，入口关闭会中止未完成的请求生命周期。
